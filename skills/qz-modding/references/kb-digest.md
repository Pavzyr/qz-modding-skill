## 1. Агентная работа: процесс, журнал, честность

### 1.1 Уровни доказательности — в каждом утверждении и в каждом отчёте пользователю
- **Метки у каждого факта** (в MODLOG, notes.md и в ответах): `[V]` видел в игре / байт-точный round-trip, `[M]` измерено, `[S]` статически (прочитал файлы/код/схему), `[H]` гипотеза. Синонимичные шкалы у других авторов: CONFIRMED / DERIVED / HYPOTHESIS / UNKNOWN; Runtime-observed / Statically confirmed / Inference / Untested. [src: techniques/evidence-levels-for-mashup-claims; games/might-and-magic-6; games/watch-dogs/shadow-engine; games/mount-and-blade-ii-bannerlord/bl2-total-conversion]
- **Статус «работает» даёт только реальный запуск**, и только для проигранных сценариев. Пишем «проверено в игре: <версия игры, ОС, что именно сделано>». Всё остальное — «собрано», «упаковано», «смонтировано», «не проверено». [src: evidence-levels]
- Что *похоже* на доказательство, но им не является: тест, который почти ничего не проверяет (проходит при любом сообщении со словом «explosion»); «скомпилировалось/упаковалось»; «действие доступно» ≠ «действие выполнилось»; «строка в логе о загрузке» ≠ «контент работает»; один ролик; несколько пересказов одного источника. [src: evidence-levels; games/gta-v; games/half-life/steve-goldsrc]
- **Извлечение ≠ понимание.** Список файлов из utoc и имена ассетов — уровень `[S]`; роли ассетов в модах-образцах — `[H]`, пока не открыты в редакторе. [src: evidence-levels]
- Чужой туториал/аддон/форум, которые мы не воспроизвели, помечаем «из источника, не проверено нами». Отчёт человека «работает» записываем как *отчёт человека* (агент видео не смотрел). Числа, вычисленные из данных, — «вычислено, не измерено». [src: detroit; far-cry-6; arkham-batman; azerothcore-modules]
- Количественные заявления — точно: «N из M», с ограничениями; не выдавать частичное за полное. [src: crysis-warhead/build-711]

### 1.2 Журнал проекта (MODLOG) — что в нём должно быть
- **Маршрут мода** называется явно и не меняется тихо; первый срез доказывает именно выбранный маршрут. [src: techniques/choosing-a-mashup-route]
- **Контракт до кода** (для сложных модов): кто чем владеет (какая система игры за что отвечает), единицы и оси, жизненный цикл (старт, пауза, смена уровня, загрузка сейва, удаление мода), что не покрыто. [src: techniques/bridge-contracts]
- **Контракт значений с колонкой «смысл»**: имя поля, значение, единицы, СМЫСЛ (из кода/ассета, который это число *использует*, а не из имени поля), источник, оракул, допуск. Пустой «смысл» — блокер. Для QZ: поля DA (`priority`, веса, `flags_mask`, `generator_layer`, FillingRule…) смотреть по базовым ассетам игры. Происхождение значения: `[extracted]` / `[derived]` / `[measured-live]`. [src: techniques/porting-a-vehicle-semantic-traps]
- Разделы: «Не проверено», «Исправления» (что было записано неверно и чем заменено — самая ценная часть), «Где записи противоречат друг другу» (две правки сразу — неизвестно, какая помогла), «Неудачные подходы» с версиями. Датировать отчёты. [src: disrupt-toolchain; evidence-levels; bl2-total-conversion; shadow-engine-findings]
- Большой мод = журнал по юнитам: «причуды сохранены», отклонения и причина, тесты, «не портировано»; готовность по уровню доказательств, а не по числу коммитов; handoff-файл для новой сессии. [src: games/minecraft/thaumcraft-port]
- **Предупреждение о возрасте данных**: всё, что записано, верно для версии игры/кита на дату записи; перепроверять после обновлений. [src: games/project-zomboid]

### 1.3 Ловушки рассуждения
- **Преждевременный вердикт** («движок отвергает X») чаще всего — неконтролируемая переменная (устаревший оглавление/кэш, старый билд). Каждый такой вердикт стоил дни и растворился при одном перемере. Ошибочный вывод сохранять в журнале как предупреждение. [src: games/just-cause-3]
- **Сначала измерить, потом теоретизировать**; при большой ошибке (другое поведение целиком) искать ошибку типа/поля, а не «дрейф». [src: techniques/bit-exact]
- **Урезанный скан выглядит чистым** → полный индекс; **близость ≠ причина** (последний в логе — не виновник) → контроль, который тоже должен упасть; **базовые частоты** → сравнивать с ванилью; **отрицательный результат скана** — проверить, что цикл покрыл весь файл. [src: games/baldurs-gate-3/act2-bisect; games/black-myth-wukong]
- **«Спящий» компонент выглядит живым**: баннер при старте ничего не доказывает; живой компонент оставлял бы следы постоянно. [src: wukong]
- **Проверять посылку** (адрес/путь/имя/«вызов внутри функции X») механически, прежде чем строить; выводы «нельзя/падает», построенные на неверной посылке, пересматривать. [src: techniques/hooking-a-host-post-world-render-pass; games/assassin-s-creed/ac4-dead-ends]
- **Не «подгонять» расхождения** (паддинг, ослабление проверки), показывать честно. [src: games/call-of-duty-black-ops/t5]
- **«Починка симптома» убирает фичу** — сначала воспроизвести внешний вид по данным, понять причину, потом менять. [src: games/world-of-warcraft/retail-armour]
- При цепочке ошибок от правки базового поведения — остановиться и найти **все места использования** (Reference Viewer), а не латать по одной. При необъяснимом поведении перечислить ВСЕ механизмы, которые могли его вызвать, и исключать по данным. [src: games/naruto-storm-4; games/world-of-warcraft/bwl-los-leak]
- **Проверять дефолт, который реально получает пользователь** («пользователь всё время играл старый режим» — тумблер по умолчанию был выключен). [src: games/terraria/melee-decomp]

### 1.4 Источники истины и чужие наработки
- Порядок: локальный кит (Python reflection, `schema/`, `qz_probe_api.py`) → моды-образцы с mod.io → ассеты игры (content-index) → документация UE/сообщества → догадки. Имена API проверять по реальному дампу, не по памяти. Утёкшие исходники/старые доки — генератор гипотез, не оракул. [src: games/cyberpunk-2077; techniques/fabric-mod-for-26-x; games/the-witcher-3]
- README может быть устаревшим — доверять коду/данным, но без round-trip держать «не проверено». [src: games/test-drive-unlimited-2/model-formats]
- **Чужие наработки быстро меняются** — в начале крупного проекта заново искать готовое (новые моды на mod.io, Discord игры, обновления кита), указывать авторство. [src: games/assassin-s-creed/community-toolkit]
- Классифицировать файл/инструмент по его содержимому, не по имени папки; автоматический сканер движка может ошибаться — подтверждать по exe/архивам. [src: games/battlefield-4; t5-zombies; kenshi]
- Инструменты, смещения и хэши не переносятся между версиями движка. [src: disrupt-toolchain]

### 1.5 Процесс и безопасность агента
- **Где есть официальный пайплайн (у QZ — ModKit + UGC-плагин) — хуки, патчи памяти и мосты «выполнить код в игре» не нужны** (RCE-поверхность, ломаются на другой сборке). [src: techniques/static-address-native-hooks; games/borderlands-2]
- Маршрут сборки ассетов по надёжности: собственные скрипты (у нас Python API редактора) > командная строка > автоматизация GUI кликами (медленно, нужен фокус, тихо портит данные). [src: techniques/editor-free-bannerlord-assets]
- Закладывать 2–10 раундов проверки человеком на фичу; «как ощущается» оценивает человек, логи этого не покажут. [src: borderlands-2; techniques/tobii]
- Крупная задача: исполнитель и отдельный проход проверки (перезапуск/перемер). Не ослаблять проверку, чтобы стать зелёным; комментарии исполнителя ревьюер не принимает как доказательство. [src: games/terraria/melee-decomp; techniques/oracles]
- **Правила затухают в длинных сессиях** — перечитывать SKILL.md и жёсткие правила периодически, особенно после сжатия контекста. [src: techniques/oracles]
- Остаточная проблема, которую нельзя исправить с уровня мода, — сузить, задокументировать, решает пользователь. Не обходить проверки целостности/DRM. Скачивание любого инструмента — с одобрения человека. [src: games/dcs-world; games/halo-ce-elden-ring]
- Пути в Python — raw-строки или `/`; heredoc/оболочка «съедает» обратные слэши. [src: crash×croc; wow-addons]

## 2. Оракулы: как доказать, что мод работает

### 2.1 Лестница проверки для QZ-мода (каждая ступень — отдельная проверка)
1. **Офлайн до кука** (секунды): `qz_validate_mod.py` (BOM, версии, метаданные, теги, секреты, пути) + `inspect`-задания в редакторе (поля DA, ссылки на ассеты, слоты материалов). Офлайн-проверка перед каждым запуском дешевле минут запуска игры. [src: games/civilization-vi; techniques/editor-free-bannerlord-assets]
2. **Упаковано**: UAT «BUILD SUCCESSFUL» + отсутствие `Error:` нашего мода в логе кука (код выхода 0 не гарантирует отсутствие ошибок) + `utoc_list.py` по готовому utoc сравнить с ожидаемым списком ассетов. Размер/сигнатура файла ничего не доказывают — читать свой результат. [src: games/call-of-duty-black-ops/t5; games/civilization-vi; techniques/havok; games/just-cause-3]
3. **Установлено ≠ смонтировано ≠ используется ≠ видно**: четыре разных проверки. В логе игры — строка монтирования pak мода; затем контент реально используется (симптом у посетителя, инструмент в руках, кампания в списке); затем визуально верен. «Ассет загрузился» ≠ «система игры его выбрала» (у них система толпы игнорировала переопределение). [src: techniques/installers; games/assassin-s-creed-iv/spawning; games/crysis-warhead]
4. **В игре, финально — только упакованный мод в Shipping-игре**, не PIE/редактор (dev-рантайм прячет проблемы релиза; бенчи проходят — релизная сборка нет). [src: techniques/a-scenario-harness; games/minecraft/bloons-td-6]
5. **Удаление**: выключить мод → перезапуск → игра как ваниль, сейв грузится. [src: games/mindustry]

### 2.2 Хороший тест
- **Тест обязан уметь падать.** Сначала убедиться, что он падает на баге; делать «мутанты» с одним дефектом и проверять, что гейт их ловит (у них 12 сломанных сборок нашли 4 ложно-зелёных результата). Для нас: прогнать `qz_validate_mod.py` на заведомо сломанном моде (BOM, GameVersion 3, без метаданных). [src: techniques/prove-your-replay-bench-can-fail; games/terraria/melee-decomp; games/minecraft/thaumcraft-port]
- **Признак, который есть ТОЛЬКО у мода**: тестовые значения/цвета/тексты заметно отличны от ванили; «совпало со стоком» ничего не доказывает; при отсутствии мода игра молча показывает базовый ассет. [src: techniques/fabric-1-20-1-gametests; games/dcs-world]
- **Доказывать требование, а не только эффект**: без условия → отказ, с условием → успех, в той же точке. [src: techniques/a-scenario-harness]
- **Контрольный прогон**: прогнать через пайплайн НЕизменённые данные (пустой мод ZZ* с одними метаданными) и убедиться, что игра его принимает, — только потом винить контент/упаковщик. [src: techniques/disrupt-toolchain; techniques/nintendo-formats; games/watch-dogs/shader-pack]
- **Один признак за раз**: менять одну константу; две правки сразу — неизвестно, какая помогла; причинный эксперимент — копия, где переключено только одно изменение. [src: techniques/bit-exact; techniques/porting-a-vehicle-semantic-traps]
- **Сравнивать с оригиналом**, а не со своей прошлой сборкой («детерминированно» ≠ «правильно»; поколение-2 vs поколение-1 доказывает только идемпотентность потерь). [src: techniques/bit-exact; games/just-cause-3]
- **Контролируемый эксперимент**: всё одинаково, кроме одного параметра; публиковать оба знаменателя (1/25 vs 24/25). [src: games/mindustry]
- Исключать посторонние модификаторы (скрытые баффы, настройки сложности, другие моды из подписок mod.io). [src: games/terraria/eye-of-cthulhu-rl]
- Наблюдение не должно менять состояние: `inspect` только читает, ничего не сохраняет. Массовый синхронный лог сам роняет FPS (эффект наблюдателя). [src: techniques/hosting-decomp; games/watch-dogs/shadow-engine-findings]
- Граничные значения из реальных проверок игры (ноль, пустой список). [src: techniques/hosting-decomp]
- Свежий мир/сейв/кампания на каждый прогон; 3 зелёных подряд перед объявлением фикса; глобальное состояние протекает между тестами. [src: techniques/fabric-1-20-1-gametests]

### 2.3 Первый провал — сначала подозревать проверку
- Первый реальный прогон массово «упал» (27/27, потом 13/27) — в основном виноват оракул: относительный путь, чекер не знал легитимного исхода игры, сценарий на ряд ниже. Разбирать каждый провал по сырым данным; после исправления чекера — мутировать данные и убедиться, что он ещё ловит дефект. Тест-обвязка сама бывает причиной (не те условия, что в игре). [src: techniques/when-the-first-real-run-fails; techniques/neoforge-gametests]
- При расхождении «должно/есть» искать ПЕРВОЕ место расхождения, а не последствия. [src: techniques/bit-exact]
- **Сначала починить инструмент, потом настраивать**; «фикс выглядит как отсутствие фикса» — скрипт упаковывал старую сборку → отказываться сравнивать, если исходники новее артефакта. Для QZ: `qz_package` — предупреждать, если zip старше последнего изменения ассетов мода. [src: games/terraria/melee-decomp]

### 2.4 Скриншоты и визуальная проверка
- **Скриншот, который никто не посмотрел, — не оракул.** Описать, что видно, и только потом читать лог; нет эталонного кадра того же ракурса — вердикт «НЕ ПРОВЕРЕНО». [src: techniques/oracles; techniques/post-world-render-hook]
- **Замёрзший оракул**: захват окна отдаёт старый кадр (одинаковый SHA-256), просмотрщик агента показывает устаревшее, харнесс «успешен» со старым PNG на диске → удалять старые артефакты перед прогоном, проверять mtime/хэш, два снимка с интервалом. Захват замирает в эксклюзивном полноэкранном режиме — окно/без рамки. [src: techniques/oracles; games/ruby-rush; thaumcraft; crash×croc]
- Короткие эффекты: догрузить сцену, триггерить эффект прямо перед снимком; короткую анимацию — запись, разложенная в сетку кадров. [src: techniques/a-scenario-harness; crash×croc]
- Запуски различаются таймингом → дифф целого экрана мало значит; снимать на паузе, свежий ванильный снимок того же состояния; не тестировать «тёмное на тёмном». [src: games/limbo]
- Смотреть в полном размере (~960 px) — так находили зеркальную камеру превью и серые пропсы. Автопроверка яркости ловит чёрные кадры. [src: games/mount-and-blade-ii-bannerlord/bl2-tc; techniques/testing-a-fabric-mod-inside-a-large-modpack]
- Лестница нового визуального элемента: появился в известном месте → правильно перекрывается и освещается → состояние игры после как до → изменение видно за известное время. [src: techniques/geometry-transfer]
- Анимации: пауза + покадровый шаг (в PIE — Pause + Advance Frame); лог смены клипа даёт временную шкалу. [src: games/left-4-dead]
- Проверка меша на чужих анимациях: контроль — тот же харнесс на стоковом меше (если ломается и он — виноват харнесс). [src: games/star-wars-battlefront-ii]

### 2.5 Лог как оракул
- Строка загрузки в логе ≠ «режим начался»: свежий лог текущей сессии + доказательство реального старта (скриншот/состояние). Для QZ: «mounted» в логе ≠ контент работает. [src: games/crysis-warhead]
- Лог надо читать целиком (баг «на один больше» стоял рядом с «на один меньше»); сравнивать с базовым шумом ванильного запуска; падать на ERROR/стектрейсах нашего плагина, а не на каждом слове «Exception». Логировать число тихих пропусков и довести до 0. [src: games/elden-ring/sunless; games/civilization-vi; thaumcraft]
- Ошибка, проглоченная `| tail`, — шаг «успешен», изменений нет → код выхода и лог каждой стадии отдельно. [src: games/civilization-vi]
- Маркер версии сборки (в описании/ассете мода), чтобы проверить, что в игре именно новая версия. [src: games/baldurs-gate-3/clothing-sorter]
- Принятие файла ≠ видимость/слышимость: дескриптор звука «играет» не значит, что слышно. Агент не слышит звук — так и писать. [src: games/crysis-warhead; left-4-dead]

### 2.6 Валидатор, растущий от ошибок
- **Каждый объяснённый крэш/ошибку превращать в правило валидатора** и чинить класс, а не фичу. Пиксельная проверка отгружаемых текстур поймала отладочную текстуру; общие константы (теги в Config/Tags ↔ теги в DA) сверять автоматически. Для QZ: `qz_validate_mod.py` — искать ассеты с именами Debug/Test/Probe, сверять теги. [src: bl2-tc; games/elden-ring/sunless; games/ruby-rush]
- Один генератор владеет производными; verify после каждой сборки (счётчики, содержимое, маркеры) — громко падать. [src: games/ruby-rush]

### 2.7 Soak и сохранность
- Soak-тест: оставить смену/кампанию на ускорении N минут, проверить, что процесс жив и ошибок в логе не больше базы. [src: games/victoria-2; games/civilization-vi]
- Сохранность: выход в меню и обратно, полный рестарт игры, установка новой версии мода — состояние сохраняется. [src: games/middle-earth-shadow-of-war]
- Отдельный лаб-сейв/профиль для тестов; сейв пользователя проверять нетронутым (mtime/хэш). [src: techniques/driving-a-game-from-a-mod-side-command-file]
- Все стенды зелёные, а у пользователя ломается — в отчёте перечислять, чего стенды не видят; финальную проверку делает человек. [src: techniques/oracles]
- Мосты «выполнить код в игре» (файл-команды Lua/Python, UE4SS) для QZ не используем — RCE-поверхность, пользователь отказался. Аналог — QzCheatManager/консоль (если доступна), логи, скриншоты, задания в редакторе. [src: games/half-sword; games/binding-of-isaac]

## 3. Запуск игры, автоматизация, процессы Windows

### 3.1 Не трогать то, что принадлежит пользователю
- **Перед запуском редактора/UAT/копированием мода проверять, не запущены ли у пользователя `QZSim-Win64-Shipping.exe` или `UnrealEditor.exe`** — если запущены, спросить. Процессы пользователя не убивать никогда; свои — только по точному PID (не `pkill -f`/по шаблону — убивали собственную оболочку). При сомнении процесс считать пользовательским (fail closed). [src: techniques/running-several-isolated-tmodloader; techniques/driving-real-games-safely; games/cities-skylines]
- **Синтетический ввод управляет реальным рабочим столом**: только с согласия, только когда человек не печатает (проверять простой), проверять фокус перед каждой серией (нажатия уходили в браузер, однажды — почти запустили онлайн). Вход в аккаунты делает только человек. [src: games/gta-v; games/kenshi; games/dishonored]
- Отдельный лаб-профиль/сейв для тестов; правки конфигов лаунчера/игры — при закрытом приложении, с бэкапом; при откате удалять только то, что создали сами (маркер). [src: games/gta-v; techniques/driving-a-game-from-a-mod-side-command-file]
- Тест-клиенты могут показывать диалоги ошибок на экране пользователя — предупреждать. [src: techniques/a-scenario-harness]

### 3.2 Запуск и управление игрой
- QZ-игру для теста запускать через Steam (прямой запуск exe с аргументами вешал последующие Steam-запуски скрытым диалогом); игра ищет данные относительно рабочей папки — запускать из своей папки. [src: games/binding-of-isaac; games/tomb-raider-legend]
- Повторные быстрые перезапуски → «зомби»-процесс без окна, лечится только перезагрузкой. Выходить штатно (меню Quit), ждать исчезновения процесса и CrashReportClient; в одном запуске проверять максимум; данные логировать ДО рискованного шага. [src: techniques/a-force-quit]
- Окно/без рамки для тестов (эксклюзивный полноэкранный режим замирает без фокуса и ломает захват); UE: `t.IdleWhenNotForeground 0`, чтобы игра не замирала без фокуса. После загрузки уровня игра ещё 10–40 с доинициализируется — ждать признака геймплея (облёт камеры, первый клик лишь подсвечивает пункт меню). [src: techniques/driving-real-games-safely; games/tunic; games/beamng]
- Слепая автоматизация меню уходила не в тот режим — ждать строку лога на каждом шаге, скриншот перед необратимым подтверждением; удержание клавиши ≥60 мс, но не 200 мс (повтор курсора). [src: games/naruto-storm-4; techniques/driving-a-game-from-a-mod-side-command-file]
- DPI-масштаб: координаты кликов логические, скриншот — физические пиксели (при 150% — сдвиг) → делить на масштаб; окно может стартовать за экраном. Скриншот может отличаться от того, что на мониторе (захват до масштабирования). [src: games/hitman/telekinesis; games/deltarune; techniques/dgvoodoo2]
- Одна загрузка уровня на процесс в скриптовых тестах; зависание без GUI — по CPU процесса. [src: games/cities-skylines; games/balatro]
- Оверлеи и инжекторы (ReShade, Bandicam, **UE4SS через dwmapi.dll у пользователя — падает на 5.7**) сами вешают/крашат игру — учитывать при разборе крэшей; не трогать без согласия. [src: techniques/a-force-quit]
- Запись ролика (если понадобится для страницы мода): захват кадров GPU (gfxcapture), звук только процесса игры (WASAPI process loopback), mkv, проверка, что звук не заглушён в микшере. [src: techniques/recording-game-footage]

### 3.3 Оболочка, кодировки, пути (Windows + Git Bash + PowerShell 5.1)
- **Кодировки**: cp1251-консоль портит кириллицу; `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8`; файлы с русским текстом — только UTF-8 без BOM, через Edit/Write или Python с `encoding='utf-8'`; сложный `python -c` с кириллицей — во временный .py. [src: games/ruby-rush; techniques/driving-real-games-safely]
- **PowerShell 5.1**: `Set-Content -Encoding utf8` пишет BOM (сломало конфиг игры) → `[IO.File]::WriteAllText(path, text, [Text.UTF8Encoding]::new($false))`; теряет вложенные кавычки в аргументах → код в файл; переменные регистронезависимы; запятые в `-File` ломают разбор; `Compress-Archive` пишет `\` в именах записей zip → Python zipfile. [src: games/gta-v; games/deltarune; games/civilization-vi; games/resident-evil-2/dlss5]
- **Git Bash/MSYS** переписывает пути-аргументы `/...` → передавать `C:/...` (`MSYS_NO_PATHCONV=1`, `cygpath -m`); некоторые инструменты (UAT, .NET) запускать из PowerShell/`cmd /c` с полным путём. `NoDefaultCurrentDirectoryInExePath=1` ломает .cmd-скрипты; `cmd /d` обходит AutoRun. [src: games/halo-ce-elden-ring; games/balatro; games/resident-evil-2/dlss5]
- Heredoc/`sed -i`/автозамена окончаний строк портят бинарные/юникодные файлы и обратные слэши; CRLF↔LF тихо ломает парсеры (git autocrlf прячет) → редактор/Python, байт-точные правки. [src: games/might-and-magic-6; games/terraria/melee-decomp; games/minecraft/neoforge]
- Пути, передаваемые игре/редактору, — абсолютные; существование файла проверять до запуска. Пути с пробелами — кавычки/junction. [src: techniques/tmodloader-labs]
- **Временные папки чистятся** (Storage Sense удалил проект из %TEMP%) → единственная копия мода/скриптов — только в постоянных папках (`QZSim/Mods/<Mod>`, `.claude/skills`), бэкапы и релизы с sha256 вне temp. Наш scratchpad — расходуемый. [src: games/ruby-rush]
- **Виртуализация**: MSIX-приложение (Claude desktop) перенаправляет записи в `%APPDATA%\Roaming\Claude\…`; Store-алиас python виртуализирует AppData; файлы из песочницы не всегда видны процессам Windows → файлы для пользователя/игры класть в обычные папки, проверять, что редактор/игра их видит. [src: games/deltarune; games/victoria-2; games/halo-ce-elden-ring]
- Долгоживущая оболочка не видит новых PATH/переменных — задавать инлайн. stdout/stderr дочернего процесса — в файл, а не в непрочитанный pipe (иначе процесс висит). [src: games/ruby-rush; games/halo-ce-elden-ring]
- Ключ API в окружении может подменить модель/учётку дочернего процесса — проверять, механически сверять цитаты. [src: games/terraria/melee-decomp]

### 3.4 Общий лог и Saved у кита и игры
- Редактор кита и игра пишут в **один** `%LOCALAPPDATA%\QZSim\Saved\Logs\QZSim.log` — после запуска редактора лог игры перезаписан; читать сразу после нужного запуска и помнить, кто писал. Копировать лог крэша до перезапуска. [src: techniques/tmodloader-labs; games/cities-skylines]
- Тяжёлые задачи (UAT, редактор) — по одной на машину; параллельные сборки конфликтуют и фризят ПК. [src: games/tomb-raider-legend; games/minecraft/bloons-td-6]

### 3.5 Единый источник констант
- Теги и имена ассетов мода держать в одном месте (манифест/MODLOG) и генерировать из него `DefaultGameplayTags.ini`, проверять ссылки — две стороны не могут разойтись. [src: games/minecraft/re2-composite]

## 4. Версии игры, совместимость, обновления, загрузка модов

### 4.1 Версия решает всё
- **Мод собирается ровно тем китом, который соответствует установленной игре** (у нас 0.9.4, UE 5.7.4+UE5-QZ, `RequiredModGameVersion=4`). Кукнутое другим кукером/версией движка игра может отвергнуть тихо. Поля версии в пакете/дескрипторе — как у ретейл-игры. Не «подделывать» номер версии, чтобы инструмент принял файл. [src: techniques/loading-pre-sequel-assets; techniques/disrupt-archives; techniques/redengine-lineage]
- **После каждого обновления игры или кита — пересобрать и перепроверить мод.** Официальный mod.io-канал не защищает: обновление Witcher 3 Remastered сломало моды, поставлявшие скрипты/строки; переиздание может обесценить все моды разом; моды с mod.io для QZ с `GameVersion 3` — пример устаревания. После патча старый инструмент писал устаревшую метку — игра молча запускалась без модов. [src: games/the-witcher-3; techniques/checking-steam-workshop-mods; games/hitman/telekinesis]
- **Версию определять по файлам, а не по документации, логу или mtime**: версия exe — из VERSIONINFO (`(Get-Item QZSim-Win64-Shipping.exe).VersionInfo.FileVersion`) + Steam buildid; версия кита — `KIT_VERSION.txt`/Build.version + `RequiredModGameVersion` в DefaultGame.ini; лог пишется при запуске (может устареть на месяцы), mtime — когда Steam записал файл. Сравнивать версии покомпонентно как числа (15.10 ≠ 15.1). [src: games/factorio; games/fallout-4; games/cyberpunk-2077; techniques/installers]
- Пост-сборочная проверка: всё, на что ссылается мод (родительские классы BP, ассеты игры, теги), существует в **установленной** версии. [src: games/risk-of-rain-2/arkham-batman]
- Иерархия доказательств совместимости чужого мода с версией: лог игры после запуска > что реально в пакете (дескриптор, версии) > маркер версии + дата обновления > стектрейсы > комментарии. «Нет жалоб» у тихого мода = никто не проверял. [src: techniques/checking-steam-workshop-mods]
- Разные билды игры могут искать метаданные/ассеты в разных путях (у одной игры папка на каждую версию, используется одна — более старые не сливаются). При смене GameVersion у QZ — сверить структуру с актуальными модами-образцами. [src: games/project-zomboid ×2]

### 4.2 Как мод попадает в игру (QZ: UGC-плагин)
- **Официальный путь — ModKit + UGC-плагин** (pak/utoc/ucas от UAT, mount `../../../QZSim/Mods/<Mod>/Content/`). Не loose-файлы, не перепаковка паков игры, не UE4SS/хуки — вывод любого «сканера» о маршруте лишь гипотеза. Свой контент живёт рядом с игровым, а не патчем поверх. [src: games/mindustry; games/no-mans-sky; games/trackmania-2]
- **pak мода монтируется при старте**: перезапись пака в запущенной игре ничего не меняет — после переупаковки перезапуск игры; новые ассеты/плагин в ките — перезапуск редактора (монтирование только существующих при старте плагинов). Живой тумблер не может изменить уже загруженные данные. [src: games/cities-skylines; games/world-of-warcraft/addons; games/watch-dogs/shadow-engine-findings]
- **utoc/ucas/pak генерирует UAT целиком — никогда не править и не смешивать файлы из разных сборок**; тройка pak+utoc+ucas одной сборки. Несоответствие оглавления содержимому = чтение мусора и крэш (у них «движок отвергает изменения» оказалось устаревшим оглавлением). [src: games/just-cause-3]
- **Кэши держат старое**: кэш по хэшу байтов держит прошлый результат; кэш карты переиспользовался после изменения; экстрактор пропускал существующие выходы → при странностях удалить `Saved/Cooked` мода (qz_package это делает), Intermediate/DerivedDataCache мода и пересобрать начисто; проверять, что игра грузит свежий pak (размер/время в логе монтирования). [src: games/megabonk; games/victoria-2; games/test-drive-unlimited/opentdu]
- Пустые/заглушечные ассеты могут регистрироваться и создавать объекты (пустой файл создал пустую войну → крэш) — не оставлять в моде пустых DA. Пути и mount point — точный регистр. [src: games/victoria-2]
- **Регистрация**: движок принимает записи только правильного типа/ключа — иное молча не подхватывается. Для QZ: DA только нужных классов (`QzSymptomDataAsset`, `QzToolDataAsset`…), теги объявлены в `Config/Tags`, UI — через `SWidgetRegistryDataAsset`, как в модах-образцах. [src: games/mount-and-blade-ii-bannerlord/bl2-tc]
- Данные, которые игра реально использует, могут лежать не там, где ожидаешь — найти через content-index/Reference Viewer, какой DA/таблицу использует игра, прежде чем добавлять своё (правка «очевидной» записи ничего не дала — использовалась другая). [src: games/binding-of-isaac; games/world-of-warcraft/retail-armour]

### 4.3 Замена vs добавление
- **Тот же путь/ключ = замена целиком; новое имя = добавление.** Замена базового DA тем же путём рискованна: после патча игры замороженная копия теряет новые поля/записи (у них пропали 18 новых поз) → после каждого обновления перекопировать базовый ассет и заново применить изменения. Предпочитать новые ассеты с уникальными именами в своей папке `/<Mod>/` и новые теги. [src: games/baldurs-gate-3/500-mod-load-order; games/darkest-dungeon]
- Порядок загрузки решает, чья замена победит; конфликт с другими модами, заменяющими тот же ассет. Зависимости — раньше зависящих. [src: games/dwarf-fortress; bg3-load-order]
- Не править файлы установки игры (проверка целостности Steam их откатит и перепишет конфиги загрузки). [src: games/dwarf-fortress; games/middle-earth-shadow-of-war]

### 4.4 Окружение пользователя: подписки, менеджеры, чужие моды
- **Подписка mod.io возвращает удалённый мод при каждом запуске**; локальная копия + подписка с тем же именем плагина = конфликт («Another plugin of the same name»). Уникальное имя плагина (ZZ* для проб), не повторять имена модов с mod.io. [src: games/baldurs-gate-3/500-mods; techniques/checking-steam-workshop-mods; games/project-zomboid/b42]
- Мод может быть выключен в менеджере модов игры (`bEnableModEnableDisableFeature=True`) — проверять, что включён; «не видно в менеджере» ≠ «не загружается». [src: games/age-of-empires-2; bg3-load-order]
- Сначала тестировать без сторонних модов/подписок и UE4SS; сравнивать логи с ними и без них прежде, чем винить свой мод. [src: techniques/fabric-in-modpack]
- Не называть установку «сломанной» и не удалять чужие загрузчики (UE4SS через dwmapi.dll у пользователя — не трогать без согласия). [src: games/cult-of-the-lamb]
- Моды-образцы из кеша mod.io не править (перезапишутся) — копировать идеи в свой мод; сначала прочитать установленные моды — они первоисточник имён классов и полей. [src: games/kenshi; games/dragon-s-dogma-2]
- Не доверять существующим строкам конфигов как эталону формата; игра держит конфиг в памяти и перезаписывает при выходе — править только при закрытой игре. [src: games/project-zomboid/b42-preset]
- Метаданные мода: парсеры ищут ключи по подстроке — `url=...?id=` перезаписал id мода. Не вставлять в FriendlyName/Description строки, похожие на ключи. [src: games/project-zomboid/b41]
- Скачанный «инструмент» может оказаться HTML-страницей — проверять размер/тип; пакеты DLC/патча с теми же именами подсовывают не тот контент. [src: games/risk-of-rain-2/arkham-batman]

## 5. Unreal Engine: что знают о движке (применимо к BP/DA мода QZ)

### 5.1 Данные и рефлексия
- Ответ на «какое поле за что» без игры даёт дамп объектов/классов (у нас `qz_deep_dump` → `schema/`, Python-рефлексия `unreal.<Class>`, `__doc__` со свойствами). Имена из рефлексии, а не имена обёрток/догадки. [src: techniques/reading-ue3-gearbox-games-offline; games/assassin-s-creed-iv/transform; games/elden-ring/cs2]
- **Обращаться к свойствам по имени, не по порядку**: у дочернего BP свои переменные идут первыми в схеме — индексы сдвигаются. Реальные имена FName бывают с пробелами (`Merchant Inventory`), у полей UserDefinedStruct суффикс `_<n>_<GUID>` — брать точные имена из дампа. [src: games/fpv-logic; games/half-sword]
- **UE5-игры типично**: сейвы `%LOCALAPPDATA%\<проект>\Saved\SaveGames`, конфиги `Saved\Config\Windows\*.ini` (у QZ так же); `.sig` рядом с pak = проверка подписи; рендер-разрешение ≠ окну (апскейлеры). Сторонние инструменты вроде UE4SS для модифицированных движков требуют отдельной настройки (VTableLayout/AOB) — этим объясняется падение старого UE4SS 3.0.1 у пользователя. [src: games/black-myth-wukong]
- Паттерн игр на UE5: один родительский BP с логикой + дочерние BP-варианты, переопределяющие компоненты (меш, override-материалы, трансформы). Это ровно наш путь для инструментов (`QZTool_UVFlashLight`/`QzTool_Electroshock` → наследник). [src: games/fpv-logic]
- Шейдеры берутся из кэша — свои мастер-материалы требуют компиляции шейдеров при куке; материалы на базе мастер-материалов игры (MaterialInstance) дешевле и надёжнее. [src: games/mount-and-blade-ii-bannerlord/bl2-tc]

### 5.2 Время жизни, порядок, состояние (BP мода)
- **Не инициализироваться слишком рано**: синглтоны/подсистемы опубликованы раньше, чем заполнены → инициализация мода после BeginPlay/по готовности подсистем, не в Construct; кадровая логика работает и в главном меню (меню — тоже сцена) → гейтить «мы в игровом уровне». [src: games/elden-ring/cs2; games/elden-ring/sunless; games/hitman/telekinesis]
- **Смена уровня/перезагрузка уничтожает созданное** → восстанавливать состояние мода на каждом BeginPlay уровня, не полагаться на объекты прошлого уровня; старые объекты до GC ещё живы — брать текущие через `GetPlayerController(0)`/`GetPlayerPawn`, а не первым из `GetAllActorsOfClass`; `FindFirstOf`-подобное может вернуть старый закрытый виджет → фильтр `IsInViewport`. [src: games/outer-wilds; games/dishonored; games/half-sword]
- **`IsValid` перед каждым вызовом** на объекте; не передавать объект «не того класса» (Cast с проверкой, IsA/IsChildOf, а не сравнение класса — наследники не совпадут). [src: games/half-sword; games/kenshi/first-person; games/project-zomboid/cdda-ants]
- **Ставить изменения туда, где игра их не перезапишет** (или в правильной фазе тика после её обновления — Tick Group); восстанавливать изменённое в любом выходе (EndPlay/Destroyed, отмена, ошибка). [src: games/kenshi/first-person; games/dragon-s-dogma-2/dimension-door; games/resident-evil-2/dlss5]
- Событие может приходить на компонент/вспомогательный объект, а не на актор → `GetOwner`. Override события в наследнике: вызывать Parent, если цель не заменить поведение (иначе «хук сработал, ничего не изменилось»); при переопределении функций родителя проверять, не ломаем ли унаследованное поведение потомков (наследование ловушка: «движение» обнулили — остановились и атаки). [src: games/let-it-die; games/cyberpunk-2077; games/world-of-warcraft/playerbots-raid]
- Предметы/инструменты спавнить так, как это делает игра (через её функции выдачи/DA), а не голым SpawnActor — получится «пустая оболочка». Проверять bool-результаты функций игры (экипировка молча отказывает в неподходящем состоянии). [src: games/half-sword; games/valheim]
- Местоположение пешки = центр капсулы; одежда/доп. меши — относительно корня скелета. UE: 1 uu = 1 см, Z-up. [src: games/dishonored; techniques/bridge-contracts]
- **Пять ступеней «работает ли»**: ассет в моде → зарегистрирован → выбран генератором/системой → заспавнен → виден/работает. Каждая — отдельная проверка. [src: games/watch-dogs/shadow-engine]
- Хук/патч низкого уровня пропускает заинлайненных вызывающих — для нас вывод: менять данные/BP через штатные точки расширения, эффект проверять в игре. [src: games/schedule-i]

## 6. 3D-модели: экспорт из Blender, импорт, скелеты, скиннинг (главный раздел для работы с пользователем)

### 6.1 Скелет — только игры
- **Скиннить строго на скелет игры с её bind-позой** (`metahuman_base_skel` для одежды посетителей, `UE4_Mannequin_Skeleton` для персонала), не на «похожий»: нативные клипы не управляют чужим скелетом (bind-позы отличаются на 7–28°), а анимации двигают и трансляции костей — **пропорции меша должны совпадать с базовым**, свой больший скелет не отправить. Лишних костей не добавлять (лимиты костей бывают «константой раскладки» — превышение тихо портит память); IK-кости (`ik_foot_*`, `ik_hand_*`) не удалять. [src: techniques/bannerlord-custom-races; techniques/editor-free-bannerlord-assets; games/star-wars-battlefront-ii; games/elden-ring/porting-dsr]
- **Собирать на частях игры**, а не одним сплавленным сгенерированным мешем: её риг, лицевой риг, LOD, шейдеры кожи; базовые части стыкуются без швов. Новые NPC-скины — переиспользовать базовые части MetaHuman/одежды и менять только нужное. Варианты одной геометрии — новые MaterialInstance/текстуры, а не копия меша. [src: games/hitman/new-suit; games/left-4-dead]
- Риг своего меша на скелет игры: ориентировать в пространство базового меша, **веса переносить с базового меша игры (Data Transfer)**, затем рисовать градиенты по регионам; невзвешенным вершинам — ближайшие веса; крупные массы (голова, наплечники) весить частично на соседние кости (иначе рвётся шея на реакциях); ≤4–8 влияний на вершину (проверить у скелета игры). Классифицировать вершины по геодезическому расстоянию, а не по боксу координат. [src: games/detroit; games/project-zomboid/cdda-ants; games/hitman/new-suit]
- **«В Blender нормально, в игре сломано» — почти всегда веса**: shrinkwrap рвёт тонкие ремни, перенос «по ближайшей грани» цепляет не те кости; жёсткие части двигать целиком. [src: games/baldurs-gate-3/outfits]
- Модель, прикреплённая к персонажу, **не наследует его анимацию** — доп. скиннед-меш на NPC: SkeletalMesh на том же скелете + Leader Pose (Set Leader Pose Component), а не attach. Аксессуары/шляпы — StaticMesh на сокете (`hat_offset/hat_extent`, `base_placement`); крепёж — к той же кости, что и основа; двигать сокет, а не меш. [src: games/world-of-warcraft/per-item-skinned; techniques/disrupt-shader-and-model; games/baldurs-gate-3/weapons]
- Поля «кость-ссылка» не должны указывать на корень (нет родителя → взрыв/зависание); масштаб персонажа не слишком мал (хит-капсулы). [src: techniques/bannerlord-native-crashes; bannerlord-custom-races]
- Самопроверки скелета до анимаций: bind × inverse-bind = единичная (~1e-6), сумма весов = 1, меш в bind-позе = исходный; затем силуэтный рендер в 3 проекциях. Сопоставлять кости по имени, не по позиции в массиве. [src: techniques/reading-source-engine-models; techniques/skinned-3d-models]

### 6.2 Экспорт из Blender — чек-лист (→ blender-handoff.md)
- **Apply All Transforms** (Ctrl+A) и к арматуре, и к мешам; никакого отрицательного масштаба (вывернутые нормали) — неприменённые трансформы удваиваются скиннингом (предмет под землёй, «тащится как флюгер»). [src: games/baldurs-gate-3/weapons; games/fpv-logic]
- **Масштаб — измерением против ванильного эталона** той же категории (инструмент, шляпа, персонаж), не «известным коэффициентом»: типичные провалы — модель в 58 м (см vs м), клинок 5 см, ×3048. UE: 1 uu = 1 см; FBX Unit Scale/Apply Scalings согласовать; после импорта читать габариты меша (inspect bounds) и сравнивать с базовым. [src: games/baldurs-gate-3/weapons-skyrim-dagger-port; games/mount-and-blade-ii-bannerlord/bl2-tc; games/halo-3-mcc]
- **Оси**: Forward/Up в FBX — сверить ориентацию с базовым ассетом на первом же импорте (инструмент смотрит, куда смотрит базовый инструмент; персонаж — лицом туда же, куда манекен); сторона лево/право может зеркалиться — определить один раз опытом и закрепить. [src: bl2-tc; games/baldurs-gate-3/weapons]
- **Пивот** = как у базового ассета (обычно ноги в 0,0,0; у инструмента — точка хвата/сокет), иначе NPC висит/проваливается, деталь качается вбок. [src: games/dead-cells; games/hitman/new-suit]
- **Add Leaf Bones OFF**; имена объектов/костей/материалов — ASCII, без пробелов и без суффиксов `.001` (дубли LOD/материалов с `.001` игра не сопоставит); простая плоская иерархия. [src: games/trackmania/2020-3d-skins; techniques/trackmania-forever-3ds-export; games/need-for-speed-shift-2]
- **Имена material slots = будущие слоты в UE** — давать осмысленные имена, совпадающие с ожидаемыми слотами базового меша; в UE слоты назначаются по индексу/имени (в DA `materials` — Map[int, Material], индекс = слот); импорты могут сортироваться по имени, а не по порядку слотов — сверять inspect'ом. Повторный экспорт может поменять имена мешей/корня — ломает ссылки. [src: games/fpv-logic; games/test-drive-unlimited-2/model-formats; games/baldurs-gate-3/outfits]
- **Нормали и тангенсы**: экспортировать Tangent Space (без тангенсов — чёрное/плоское затенение); Face Orientation overlay — синих граней снаружи нет, Recalculate Outside (вывернутые грани Blender прячет, в игре — тёмное освещение). [src: games/civilization-vi; games/world-of-warcraft/per-item-skinned]
- **Модификаторы применять осознанно**: EDGE_SPLIT и пр. меняют число/порядок вершин — индексы и веса «съезжают» (шипы). Сварить вершины до децимации, иначе LOD шипастые. [src: games/star-wars-battlefront-ii; games/hitman/new-suit]
- **UV в 0..1**, если материал не тайлит; второй UV-канал (UV1) в UE — lightmap (не путать: у одной игры альфа диффуза = AO по второму UV). Отладочная текстура с цветными зонами/номерами отвечает на вопросы раскладки за один запуск. [src: games/trackmania/2020; games/star-wars-battlefront-ii; games/elden-ring/sunless]
- **Vertex Color**: важен на персонажах — при импорте Import/Replace/Ignore согласовать с материалом игры. [src: games/hitman/new-suit]
- Анимации — один take на FBX (мультитейк записал ключи первого во все — «все анимации = поза смерти»). [src: techniques/editor-free-bannerlord-assets]
- Версии Blender/экспортёра — записывать в MODLOG; сначала round-trip одного стокового ассета. [src: games/kenshi/recon]

### 6.3 Импорт в UE и проверка в редакторе
- Импорт только через Python API редактора (`qz_mod_job.py import`), не кликами. После импорта: габариты (bounds) против базового меша; Skeleton = скелет игры; Physics Asset для своих скелетных мешей (без него — нет попаданий/рэгдолла; покрытие капсул мерить, а не на глаз); bounds/Positive-Negative Bounds Extension (пустые bounds → невидим под углами/застревает на LOD). [src: techniques/editor-free-bannerlord-assets; games/elden-ring/porting-dsr]
- **Бюджет полигонов** сверять с базовыми мешами той же категории (inspect num_triangles/LOD); у одной игры превышение на любом LOD молча возвращало дефолтный скин. Ориентиры из базы знаний (не QZ): тело ~12k трисов (2048 цвет / 1024 нормаль), оружие ~3.5k, объект ~25k. [src: games/trackmania/2020; games/risk-of-rain-2/helldiver; games/civilization-vi]
- **LOD**: объект исчезает на расстоянии / все LOD сразу — неверные дистанции; унаследованные от донора LOD-настройки при одном LOD0 → исчезает; для одежды без своих LOD — один LOD0 или Auto LOD (Reduction) в UE. Проверять, отводя камеру. [src: games/baldurs-gate-3/outfits; bg3-weapons; games/fpv-logic]
- **Слоты материалов не решают, какие меши рисовать** — чтобы убрать часть, удалить её из меша; под удалённой частью может оказаться скрытая геометрия. [src: games/baldurs-gate-3/outfits]
- **Одежда и маски тела**: маскировать только то, что реально покрывает меш (иначе «дырка» — невидимая лодыжка); каждая часть несёт свои маски; поддержка типа тела = свой визуал для этого типа тела (`Clothing/<Slot>/<Female|Male>/<MediumAverage|…>`) — покрывать нужные типы тел или ограничиваться ими. У `QzClothingItemDataAsset` 38 полей — найти, какие отвечают за маски/скрытие. [src: games/baldurs-gate-3/outfits; bg3-clothing-sorter]
- Физику ткани не видно на скриншоте — проверять в движении. [src: games/baldurs-gate-3/outfits]
- **Не подменять меш в рантайме мимо системы скинов игры** (она переприменяет свой меш и «мигает») — NPC-скины только через DA (`QzStaticNPCSkinDataAsset`). [src: games/risk-of-rain-2/helldiver]
- Секции/материалы при правке мешей игры не перемешивать (порядок секций и диапазонов сломал все лица). [src: games/world-of-warcraft/hd-character-customization]
- Прежде чем менять DA/меш — найти, какой именно ассет использует игра для нужного контента (правка «очевидной» записи ничего не дала). [src: games/world-of-warcraft/retail-armour]

### 6.4 Оптимизация (если модель тяжёлая)
- Blender: сварить, децимировать (vertex groups сохраняют веса), Smart UV + pack, Cycles bake selected-to-active (цвет + tangent-space нормаль), MikkTSpace-тангенсы — у них 209k → 30k вершин, 48 → 13 МБ текстур, FPS 318 → 420. [src: games/risk-of-rain-2/helldiver]
- Для жёстких CAD-моделей упрощение с учётом швов застревает — упрощать по позициям, потом возвращать нормали/UV. [src: games/fpv-logic]
- AI image-to-3D (если пользователь пойдёт этим путём): одна чёткая силуэтная форма на концепт; сложные (деревья, шпили) выходят плохо; превью с игровой камеры. [src: games/civilization-vi]

## 7. Материалы, текстуры, шейдеры

### 7.1 Материалы — от материалов игры
- **Только MaterialInstance от мастер-материалов игры той же категории** (одежда — от материала одежды, инструмент — от материала инструмента): шейдеры уже скомпилированы в игре, обязательные карты/параметры заданы, вьюмодель инструмента не клипается сквозь стены. Свой мастер-материал = новые шейдеры в ShaderArchive мода (так делают некоторые моды с mod.io) — тяжелее и рискованнее. Не кидать персонажный материал на пропы. [src: techniques/editor-free-bannerlord-assets; techniques/loading-pre-sequel-assets; games/outer-wilds; games/hitman/new-suit]
- **Usage-флаги**: материал для SkeletalMesh — `Used with Skeletal Mesh` (и др. usage) заранее, в кукнутой игре новые пермутации не скомпилируются → серый WorldGrid/чёрный меш. [знание UE + src: techniques/editor-free-bannerlord-assets]
- **Цепочка: меш → слоты материалов (по имени/индексу) → MI → текстуры.** Меш ссылается на материал, а не на текстуры: переименовали текстуры без материала — белый меш. В DA `materials` — Map[int, Material], индекс = слот. Два слота с одним материалом/индексом — проверить, что не «наследуют» не то (у одной игры загрузчик копировал шейдер соседней секции). [src: games/elden-ring/sunless; games/world-of-warcraft/retail-armour]
- Пресет/параметр цвета может «протечь» на все части с тем же параметром — отдельный MI на каждую вещь; цветовой параметр должен быть локальным (глобальный перекрасил весь экран). Имена параметров MI = имена параметров в родительском материале — смотреть в базовом MI. [src: games/baldurs-gate-3/outfits; games/dragon-s-dogma-2/dimension-door; games/borderlands-2]
- **Прежде чем верить имени параметра** — посмотреть, как он используется у ассетов игры (флаг есть у всех материалов, а работает только на карте). Прежде чем «чинить» цвет — проверить оригинал (заметка говорила «красный», а в игре жёлтый). [src: games/elden-ring/sunless; techniques/skinned-3d-models]
- Состояние материала (Blend Mode, Opacity, Masked, Two Sided) переносится отдельно от пикселей: плоский меш с односторонним материалом невидим сзади → Two Sided; мех стал непрозрачным при потере режима смешивания. [src: games/borderlands-2; games/crysis-warhead]
- Override материалов по имени у одной игры не сработал, а override меша — сработал; проверять оба пути, если что-то «не применилось». [src: bl2-tc]

### 7.2 Текстуры
- **Перед заменой текстуры открыть базовый материал/MI и понять каналы** (маски ORM, tint-параметры, что в альфе): текстуры игр часто не «картинка как есть» — альфа бывает маской спекуляра/AO/self-illum, а не прозрачностью; чёрный альбедо + цвет из нормалей/градиентов. Альфа случайно не должна включать Masked/Translucent (дыры, выцветание). [src: games/dead-cells; games/halo-3-mcc; games/portal-2; source-mdl]
- **Нормали**: UE ждёт DirectX-стиль (Y−), Blender/Substance по умолчанию OpenGL (Y+) → экспортировать DirectX или при импорте `flip_green_channel=True`; признак ошибки — «вдавленные» выпуклости при боковом свете. Нормали и маски — sRGB off, compression Normalmap / Masks. [знание UE + src: techniques/redengine; games/crysis-warhead]
- **Размеры — степени двойки** (512/1024/2048), иначе UE не делает мипы/стриминг; размер не больше, чем у аналогичных ассетов игры; сжатие стандартное (BC1/DXT1 без альфы — вдвое меньше; BC3/DXT5 с альфой; несжатые раздувают мод — 14 портретов = 157 МБ). Текстуры без альфы экспортировать без альфа-канала. [src: thaumcraft; games/world-of-warcraft/texture-crashes; games/civilization-vi; games/risk-of-rain-2/helldiver]
- Лимиты клиента у одной игры: >1024 px и несжатые текстуры крашили при смене ползунка качества → проверять мод и при низком качестве текстур в настройках QZ. [src: games/world-of-warcraft/texture-crashes]
- **Яркость своих текстур** часто ниже игровых (сгенерированные: альбедо 0.03–0.07 против 0.15–0.33) и есть чёрный паддинг UV → залить паддинг, выровнять яркость, сравнивать с текстурами игры **в игровом освещении/цветокоррекции** (LUT игры меняет цвета). [src: games/civilization-vi; games/halo-ce-elden-ring; techniques/editor-free]
- Правка только уровня 0 оставляет старые мипы — в UE править исходник и реимпортировать (мипы регенерируются). UI/«цифровые» текстуры — TextureGroup UI, без мипов (иначе размываются). [src: games/limbo; games/elden-ring/cs2]
- Перекраска: менять только карты, несущие цвет; в HSV «защёлкивать» оттенок; нормали/маски не трогать. [src: games/baldurs-gate-3/outfits]
- Подмена UI-текстуры не того размера вешала игру на экране загрузки (выглядело как «битый сейв») → подмены — тот же размер/формат, что у оригинала; при зависании — бисекция по ассетам мода. [src: games/binding-of-isaac]
- Тёмная кайма у иконок — неверная премультипликация альфы/фильтрация. [src: games/underrail; techniques/skinned-3d-models]

### 7.3 Эффекты
- Масштабирование якоря эффекта делало его невидимым; заимствованные эффекты сами не выключаются — хранить ссылку и завершать; клон способности уносит большие эффекты запуска — вычищать. Для QZ Niagara/GameplayCue в клонированных BP — проверять унаследованные эффекты/звуки. [src: games/dragon-s-dogma-2; games/valheim]

## 8. Анимации
- Если пользователь даст анимации: **таблица клипов как данные** (кандидат, обрезка, скорость, зеркало, обработка root — снять XY / зафиксировать yaw), один take на клип, после экспорта — повторный импорт и проверка: все клипы пришли один раз, длительность верна. [src: games/risk-of-rain-2/arkham-batman]
- Root motion: In Place vs Root Motion согласовать с AnimBP игры; чужие клипы атак развёрнуты на жертву — фиксировать yaw; не кроссфейдить уже замкнутые петли (запинка), сначала измерить замыкание. [src: arkham-batman]
- Аддитивные клипы требуют базовой позы и применяются относительно первого кадра (иначе A-поза); экспорт может удвоить поворот корня (Z-up→Y-up дважды). Масштаб импорта анимации = масштабу рига. [src: games/call-of-duty-black-ops/t5; games/elden-ring/cs2; arkham-batman]
- «Атака» может быть пустой заглушкой, а удар — в слое поверх бега; переключение по порогу дребезжит → гистерезис; растягивать клип на интервал события. Логика (урон, звук, флаги) может висеть на AnimNotify — отключая анимацию/эффект, проверять, что не отключили логику. [src: games/left-4-dead; games/naruto-storm-4]
- Вторичная физика (Physics Asset/Cloth): параметры брать по образцу базовых ассетов игры «как хранятся», не переинтерпретировать ради вида; «устаканивание» мерить по позе, не по скорости. [src: games/world-of-warcraft/item-physics]
- Проверка: пауза + покадровый шаг; превью своего меша на анимациях базового NPC (Preview Mesh в AnimSequence). [src: games/left-4-dead; games/star-wars-battlefront-ii]

## 9. Аудио
- **Звук только через систему игры**: SoundWave/SoundCue/MetaSound + Sound Class/Submix игры (тогда работают слайдеры громкости); сторонние пути могут молчать (у одной игры аудио движка было отключено). [src: games/risk-of-rain-2/arkham-batman; games/project-zomboid/cdda-ants]
- **3D-звуки — моно WAV** (стерео не позиционируется и не затухает); стерео — UI/музыка. Зацикленные (гул, вентиляция) — Looping/loop-точки. [src: games/minecraft/bloons-td-6; games/need-for-speed-most-wanted-2005]
- **Тестовый звук — уникальный** (стоковый звук не докажет, что загрузился наш). Клонированный ассет уносит громкость/питч/рандом родителя (−21 дБ, −280 центов) — сбрасывать в нейтраль; Volume/Pitch multiplier, Attenuation проверять. Звук предмета: надёжнее скопировать целиком ванильный ассет того же типа, который звучит правильно. [src: games/elden-ring/porting-dsr; games/baldurs-gate-3/outfits]
- Громкость новых звуков выравнивать по звукам игры (±1 дБ): нормализация → обрезка тишины → лимитер. Против спама — Concurrency (ограничение одновременных/в секунду), вероятности. [src: games/project-zomboid/cdda-ants; bl2-tc]
- Агент звук не слышит — «громкость не проверена» писать честно; «звук запрошен» ≠ «прозвучал». [src: games/left-4-dead; games/crysis-warhead]
- Middleware-банки (Wwise/FMOD), если когда-то понадобятся, — собирать ровно той версией, что в игре. [src: techniques/wwise; bl2-tc]

## 10. UI / меню / локализация
- **UI мода — UMG-виджеты в моде + регистрация через `SWidgetRegistryDataAsset`** (как моды-образцы), расширение через штатные точки, а не перезапись базовых виджетов игры. Новые экраны собирать из виджетов/стилей/шрифтов игры — выглядят как родные. Переиспользовать существующие экраны игры, где можно. [src: games/civilization-vi; games/the-dark-legions; games/naruto-storm-4; games/test-drive-unlimited-2/vmf]
- **Тексты — FText/StringTable мода со своим уникальным неймспейсом** (`ST_<Mod>_*`): локализация с именем базового файла у одной игры заменила ВСЮ таблицу — все тексты игры пропали; DLC-таблица текста — полная замена базовой; текст мода затирался модом, грузящимся позже. Не трогать базовые StringTable. [src: games/darkest-dungeon; games/elden-ring/sunless; games/civilization-vi]
- **Заполнять все текстовые поля нового DA** (имя, описание) — пустая локализация давала NullReference в GetName у новых предметов; без ключа видно сырой ID. [src: games/megabonk; games/hearts-of-iron-iv]
- Проверять загрузку всех строк (счётчик): битый формат (комментарий не там) — загрузилось 9 из 794; `%` в подписях ломал форматирование; апострофы ломают строки в кавычках. [src: bl2-tc; games/project-zomboid/cdda-ants; games/cities-skylines]
- **Язык пользователя — русский**: проверять отображение кириллицы (шрифт игры её покрывает?), тексты длиннее английских — боксы с запасом (у одной игры текст в боксе ниже строки не рисовался вовсе — ≥1.45 × размер шрифта); тестировать мод минимум на RU и EN; не-ASCII в полях ввода разрешать. [src: games/mewgenics; games/schedule-i; games/the-dark-legions]
- Иконки: несколько мест поиска (планшет `T_*_Icon`, колесо `T_*_Wheel`) — проверять каждое; ракурс/фон как у иконок игры; неправильная ориентация модели — иконка-«клякса». [src: games/baldurs-gate-3/outfits; techniques/editor-free; games/terraria/fal-arsenal]
- Кнопки: после клика кнопка становится выбранной и Submit жмёт её повторно (дублирование денег) → IsFocusable=false/навигация off у кнопок мода, защитный интервал на важных действиях. Модальный UI держит блок ввода до отпускания клавиши, иначе нажатие «протекает» в игру. [src: games/schedule-i; games/elden-ring/sunless; games/deltarune]
- Клавиши мода — не занятые игрой/другими модами, переназначаемые; проверить Enhanced Input контексты (IMC) игры; лучше переиспользовать существующие действия инструментов. [src: games/outer-wilds; games/minecraft/bloons-td-6]
- Логика мода — в BP-функциях/событиях, вызываемых без UI; виджеты только показывают состояние (тестируемо без экрана). Не дублировать штатные счётчики HUD. [src: games/minecraft/bloons-td-6; games/crysis-warhead]
- Найти, какой виджет игры отвечает за экран, — поиск строки/имени по content-index/Reference Viewer. [src: games/watch-dogs/feu-gfx]

## 11. Данные игры: data-ассеты, теги, генераторы, баланс

### 11.1 Клонировать, а не писать с нуля
- **Новый DA/BP = Duplicate заполненного базового ассета того же типа**, затем менять только нужное. Пустой Create теряет скрытые дефолты (у одной игры урон 7 вместо 47; у другой нет обязательных ключей статов → KeyNotFound на первом ударе; рукописный ресурс «пакуется и ничего не рисует»). [src: techniques/bannerlord-combat; games/megabonk; games/baldurs-gate-3/outfits; games/assassin-s-creed/spawn-working-route]
- **Отсутствующее поле = дефолт из определения, не ноль**: перед `set` прочитать текущее значение (`inspect`), писать только отличающиеся. При Duplicate поля наследуются от источника. [src: games/elden-ring/sunless]
- **Клон должен переписать самоссылки и все внутренние ссылки**: поля, указывающие на сам базовый ассет, его теги, `item_data_asset`, меш → материалы → BP — на свои копии; забытые ссылки на старый ID давали крэш при приближении; клон способности уносил «категорию вытеснения» и эффекты. Пройти цепочку наследования родителя (родитель молча добавлял статы). [src: games/elden-ring/sunless; games/elden-ring/porting-dsr; games/baldurs-gate-3/outfits]
- Скопировать точную форму из **уже работающего ассета/мода**, делающего то же самое; «нет в ванили» — стиль, а не запрет — посмотреть, что делают моды-образцы. [src: games/baldurs-gate-3/outfits]
- Самый дешёвый маршрут: варианты через материалы/цвета/комбинации базовых ассетов, и только потом новые меши. [src: techniques/disrupt-engine-shader-and-model-modding]
- Ассеты менять только через редактор кита (Python API), не правкой бинарников и не через экспортированные текстовые «сайдкары» (игра читает бинарный ресурс). [src: games/cities-skylines/modding-api; games/assassin-s-creed/toolkit]

### 11.2 Новое рядом с ванилью, а не вместо
- **Новый контент — свой ID/тег/путь, сосуществующий с ванилью**; базовые теги/DA не удалять и не переименовывать (на них ссылаются ИИ, генераторы, сейвы); схема своих имён — префикс мода, документирована в MODLOG. В данных игры может уже быть «похожее имя» — проверять уникальность. [src: games/civilization-vi; games/elden-ring/porting-dsr; games/middle-earth-shadow-of-war]
- **Подмена базового ассета тем же путём = замена всего определения**, не патч поля; она действует во всех кампаниях/днях/сейвах — предупреждать в описании; после обновления игры переприменять. Предпочитать новый DA с новым тегом. [src: games/dcs-world; techniques/reading-ue3-gearbox-games-offline]
- Если задача — переделать существующий предмет (так попросил пользователь), допустимо мутировать ванильный ассет, понимая последствия для сейвов. Внутреннее имя ≠ отображаемое — искать по content-index. [src: games/valheim]
- **Встраиваться в существующие системы** (теги, генераторы, дни, кампании, `generator_data_source=Mod`), а не заменять их. [src: techniques/rebuilt-guest-engine]

### 11.3 Как игра выбирает контент (проверять, что наше вообще выбирается)
- **Данные загрузились ≠ система их выбрала**: роль брала ПЕРВУЮ валидную запись (второе значение в списке — ничего); UI/предикаты проверяли конкретный список, куда новое значение надо добавить; хардкод-таблица UI не показывает новое. Для QZ: проверять видимость в меню кампаний, планшете, колесе инструментов, у посетителей; найти, где генератор (`QzGeneratorParentPrimaryData`, `key_tag_data`, FillingRule) берёт кандидатов. [src: games/middle-earth-shadow-of-war; games/age-of-empires-2]
- **Имена/префиксы несут смысл**: ключи вида `Generator.DataKey.<Cat>.<Sub>.<Asset>`, `Symptom.Virus.*` (только у заражённых); движок может выводить поведение из имени — соблюдать соглашения игры. [src: games/balatro]
- **Порядок и сортировка в таблицах**: новые записи в индексируемых/отсортированных таблицах — пересортировать или соблюдать группировку как у базовых (новое племя превращалось в другое после загрузки; строки вне блока сломали выбор лица у всех); иконки/элементы могут браться по индексу, а не по ключу. [src: games/middle-earth-shadow-of-war; games/world-of-warcraft/hd-customization; games/victoria-2]
- **Семантику полей узнавать по поведению игры**, а не по имени: «шанс 0» в группе = делёж остатка, а не «никогда»; флаг с «очевидным» именем значит другое; «щит» оказался наручем. Таблицы смыслов (редкость, уровни) — из данных игры. [src: games/world-of-warcraft/azerothcore-modules; games/elden-ring/sunless; games/halo-3-mcc; games/borderlands-2]
- Новое может требовать полного набора сопутствующего (категория, коллизия, иконка, текст) — иначе крэш или «не появляется». Для QZ инструмент = DA Tool + ID_ ItemData + BP-наследник + иконки `T_*_Icon/_Wheel` + тексты; симптом = DA_Symptom + BP_GA_* + рентген-маркер + тексты; кампания = DA_Company + DAY_* + DA_Level + карта + rules BP + LossConditions + UI CampaignCard. [src: bl2-tc; mod-patterns.md]

### 11.4 Состояние и пересчёт
- **Сохранённые объекты держат свои значения** — правка DA может не повлиять на уже существующее в сейве → тестировать на новой кампании/смене. Некоторые изменения требуют новой кампании вовсе. [src: games/let-it-die; bl2-tc]
- Игра пересчитывает значения (смена экипировки, рост, загрузка) и перезаписывает выставленное → править источник (DA), а не рантайм-копию; при множителях хранить исходные значения (клоны копируют текущее — множители копятся). [src: techniques/bannerlord-combat; games/schedule-i; games/project-zomboid/cdda-ants]
- DA не использовать как изменяемое рантайм-состояние (общий для всех экземпляров) — состояние в акторе/компоненте. Значения менять через функции игры (Set*/Add*), а не в кэше виджета. [src: games/risk-of-rain-2/arkham-batman; games/let-it-die]
- Эффекты/способности — через GameplayEffect/Ability игры (нативная обработка), с уникальными тегами блокировки/отмены; клоны эффектов наследуют категории/теги, которые тихо конфликтуют с чужими. [src: games/the-king-of-fighters-xiii; games/elden-ring/sunless]
- Тестировать через обычный игровой поток (новая кампания/день), а не искусственными вызовами — спавн «в обход» даёт неполное состояние. [src: techniques/bannerlord-combat; games/half-sword]
- Не использовать «магические» значения в полях с клампом (9999 HP → читалось как огромный урон). [src: games/tunic]

### 11.5 Баланс и генерация
- Числа баланса — из данных игры, масштабировать от них; проверять в игре («3 выстрела на 50 HP, как в оригинале»); финальные числа подбираются с человеком «по ощущению» — фиксировать итог. Фактическая цена/значение в UI может отличаться от данных (×2). [src: games/half-life; games/left-4-dead; games/half-sword]
- Рандомизация/генерация: сохранять полярность бонус/штраф; глобальный множитель + малый разброс вместо независимых бросков (иначе длинные задания платят меньше); отдельный сид на секцию; значение, объявленное в двух местах, бросать один раз; парные поля менять вместе. [src: games/darkest-dungeon]
- Аудит всего, что может производить новый контент (награды, магазины, генераторы), — цена/редкость адекватны. [src: bl2-tc]
- **Массовый контент — генератором**: скрипт читает источники, строит матрицу совместимости, генерирует job.json для `qz_mod_job`, прогоняет самопроверки до упаковки; выпускает человекочитаемый «спойлер»; пишет только в папку мода и стирает её только при наличии маркера «создано мной». Всё воспроизводимо — ничего руками в папке мода. [src: games/baldurs-gate-3/clothing-sorter; games/darkest-dungeon; games/victoria-2]
- ИИ-логика NPC (BP): учитывать переходы состояний, дубликаты, повторную отправку одного действия (применять один раз), запретные зоны. [src: games/minecraft/kindred; games/mount-and-blade-ii-bannerlord/bannercraft]

## 12. Упаковка, публикация, лицензии

### 12.1 Сборка и упаковка
- **Проверенный путь — UAT BuildCookRun `-DLCName`** (`qz_package.py`); свой упаковщик не изобретать (у других игр «standalone-пакер» оказывался непригоден). Одна сборка за раз на машину; не собирать, пока у пользователя открыты игра/редактор. [src: games/the-witcher-3; games/minecraft/bloons-td-6; games/world-of-warcraft/server-ops]
- **Сборка не должна перезаписывать установленное у пользователя** (у них сборка дважды затёрла установленный мод игрока): собирать в стейдж (`$QZ_MODS_OUT/<Mod>/Builds/`), хэш/mtime установленного до и после; бэкап до первой сборки. Не держать рядом упакованную и «рассыпанную» копию одного мода (грузятся обе) — локальная `QZSim\Modio\<Mod>` + подписка = конфликт. [src: techniques/testing-a-fabric-mod-inside-a-large-modpack; techniques/editor-free-bannerlord-assets]
- **Устаревшие выходы сборки** (неудачные/частичные) переживают пересборку → удалять выходные папки и `Saved/Cooked` мода перед пересборкой (qz_package делает); «правки не подействовали» — пересобран ли бинарный ассет после правки исходника (гейт по mtime: исходники новее артефакта → предупреждение). [src: games/star-wars-battlefront-ii; games/baldurs-gate-3/outfits; games/terraria/melee-decomp]
- **Гейты до упаковки** (qz_validate_mod.py + inspect): имена/пути ассетов уникальны и не совпадают с `/Game`; каждая ссылка разрешается; теги объявлены; формат ID корректен; **длина пути для кука** (`EditorAssetSubsystem.get_asset_filename_length_for_cooking`) в пределах лимита (у них слишком длинное имя — фатальный крэш при старте); обрезка имён не создаёт коллизий; нет отладочных/пробных ассетов. [src: techniques/editor-free; games/baldurs-gate-3/clothing-sorter; games/baldurs-gate-3/weapons]
- **Структурированные файлы (uplugin/json/ini) править парсером**, не текстовой заменой (замена задела чужую запись); правки чужих файлов — «патчем с якорем» (падать, если фрагмент найден 0 или 2+ раз); перед изменением проверять ожидаемое исходное состояние; запись — временный файл + атомарная замена с усечением (переупаковщик без усечения оставлял старый хвост). [src: games/age-of-empires-2; techniques/hosting-decomp; games/test-drive-unlimited-2/containers]
- **Версионировать мод**: повышать версию при каждой пересборке, ID/имя плагина не менять; поле версии в job.json; отказ при несовпадении GameVersion/EngineVersion кита. [src: games/baldurs-gate-3/load-order; techniques/bridge-contracts]
- **Готовый zip**: метаданные в корне ожидаемой папки (лишняя папка рядом ломает распознавание), имена записей с `/` (PowerShell Compress-Archive пишет `\` — используем Python zipfile), прочитать обратно (`testzip`) и сверить со списком utoc; печатать SHA-256 протестированного zip; хранить предыдущий рабочий zip для отката. [src: games/mindustry; games/resident-evil-2/dlss5; games/world-of-warcraft/texture-crashes; games/just-cause-3]
- Без uplugin + UUGC_Metadata pak не смонтируется (аналог «архив без плагина-дескриптора» у Bethesda). [src: techniques/bethesda-esl]

### 12.2 Что можно и что нельзя класть в мод
- **В мод — только своё**: никаких файлов игры/кита, конвертированных ассетов других игр, декомпилированного/утёкшего кода, чужих рантаймов/SDK. **`DefaultGame.ini` кита содержит ApiKey mod.io — никогда не копировать конфиги кита в мод** (qz_validate_mod ищет секреты). [src: techniques/publishing-reverse-engineering-research; techniques/tobii; games/terraria/melee-decomp]
- Модели/текстуры из других игр (если пользователь захочет) — только личная локальная сборка, не mod.io («два пакета: личный и share-safe»). Имена и арт правообладателей — не в название/превью мода. [src: games/risk-of-rain-2/helldiver; games/terraria/melee-decomp]
- Ссылаться на чужой контент (другой мод) по ключу/тегу, а не копировать его; клон с исходным ID переопределяет оригинал — клонировать с новыми именами; мягкая зависимость требует загрузки источника раньше. [src: games/baldurs-gate-3/clothing-sorter; bg3-weapons]
- Порт/адаптация чужого мода — только с разрешения автора, с указанием авторства; лицензии ассетов (CC BY-SA, ISC и т.п.) — в описании. Кредиты инструментам и знаниям сообщества. [src: games/project-zomboid/b41; games/project-zomboid/cdda-ants; games/elden-ring/porting-dsr]
- Тестовые моды с перекрашенными ассетами игры — только локально, не публиковать (наши пробные ZZ* удаляются). [src: games/darkest-dungeon]
- Сгенерированный ИИ арт: раскрыть в описании; не делать сходство с реальными людьми; платные генерации — один последовательный генератор, оценка цены и вопрос перед пачкой, манифест генераций с сидами. [src: games/civilization-vi; games/ruby-rush]
- Не обходить проверки владения/DRM/целостности и не давать играть без владения (их первый установщик так делал — поймано на ревью). [src: games/portal-2/portalcraft; games/star-wars-battlefront-ii]
- Антивирус пометил наши файлы — не добавлять исключения и не выключать защиту, сказать пользователю. [src: games/world-of-warcraft/per-item-skinned]
- Моды, дающие преимущество, — не для онлайн-лидербордов (если появятся у QZ — предупреждать). [src: games/megabonk; games/hitman]

### 12.3 Публикация (делает пользователь; мы готовим)
- **Публикует на mod.io пользователь**; мы готовим zip, описание, превью и чек-лист. Требования сайта (превью 16:9, размеры, описание, теги) — уточнить перед первой публикацией; «валидатор сайта» — реальный оракул требований. [src: games/trackmania-2]
- На странице мода — версия игры/кита, под которую собран, дата, что проверено и что нет. [src: techniques/checking-steam-workshop-mods]
- Чистка перед публикацией: литеральный поиск `C:\Users\`, `C:/Users/`, имени пользователя, внутренних имён, ключей; секреты удалять, а не переносить; после чистки — «огрызки»; проверить сборкой. Линт «нет файлов игры» сравнивает с установкой, а не с самим модом (junction внутри игры даёт ложные срабатывания). [src: techniques/publishing-reverse-engineering-research; games/dwarf-fortress; games/binding-of-isaac]
- Данные игры (распакованное, дампы, `schema/`, content-index) держать локально, вне публикуемого. [src: techniques/reading-ue3-gearbox-games-offline]

## 13. Сейвы и совместимость сейвов
- **Перед тестами мода — бэкап сейвов пользователя** (`%LOCALAPPDATA%\QZSim\Saved\SaveGames\76561198154708427`), попросить его сохраниться; после — сравнить/восстановить с его согласия. Кампании/режимы могут перезаписать сейв при загрузке. [src: games/cities-skylines/dashboard; games/half-sword]
- **Самому прогнать: загрузка → игра → СОХРАНЕНИЕ → выход → загрузка**, запуская игру тем же способом, что игрок (через Steam). Затем выключить мод и проверить, что сейв грузится (сейв QZ хранит теги — деградирует тихо). [src: games/cities-skylines; games/schedule-i; games/baldurs-gate-3/load-order]
- **Стабильные ID**: не переименовывать теги, KeyTag, пути ассетов мода между версиями — сейв хранит теги; структурная переделка с новыми ID = новая версия «с нуля». [src: games/baldurs-gate-3/clothing-sorter]
- Мод не должен класть в сохраняемое состояние временные/на лету созданные объекты — только реальные ассеты и стабильные теги; новое содержимое DA может не применяться к уже сохранённым объектам — тестировать на новой кампании/смене. [src: games/borderlands-2; games/let-it-die; games/project-zomboid/b41]
- Сейвы руками не правим. Если когда-нибудь — только при закрытой игре, с бэкапом и атомарной записью. Редакторы сейвов от другой версии портят. [src: games/let-it-die; games/test-drive-unlimited-2]
- Конфиги: сохранять окончания строк (CRLF/LF как у оригинала) и кодировку; запись во временный файл + атомарная замена; после записи перечитать (баг одной игры: писатель LF, читатель CRLF → все настройки молча сбрасывались). Временные настройки мода не должны попасть в GameUserSettings пользователя. [src: games/the-dark-legions; games/watch-dogs/shadow-engine-findings; games/terraria/melee-decomp]
- Тест-действия, меняющие мир/прогресс (награды, достижения, читы), — с отменой; читы могут отключать достижения Steam — предупреждать. [src: games/portal-2/portalcraft]
- Онлайн/лидерборды: моды, дающие преимущество, туда не пускать (если у QZ появятся лидерборды/статистика — предупреждать). [src: games/megabonk; games/halo-trial]

## 14. Производительность, крэши, отладка

### 14.1 Порядок разбора проблемы «мод не работает / игра падает»
1. **Ваниль на том же ПК** — проблема без мода? (блеклые цвета, диалог настроек, крэш драйвера оказывались не модом). Пустой мод ZZ* как контроль. [src: games/resident-evil-2/dlss5; games/tomb-raider-legend; games/just-cause-3]
2. **Загрузился ли вообще?** Прежде чем реверсить, доказать, что мод/ассет/тег загружен: лог монтирования (`Mounted mod source`, `Added UGC plugin`, регистрация UGC GameplayTags), маркер версии мода. Сутки уходили на теории, а файлы просто не читались. Новая сборка — именно та, что думаешь (хэш/версия в логе); «выключенная» в тесте фича на деле не была выключена. [src: techniques/editor-free-bannerlord-assets; games/dragon-s-dogma-2/dimension-door]
3. **Лог — скопировать сразу** (UE перезаписывает при следующем старте; есть `QZSim-backup-*.log`); помнить, что редактор кита пишет в тот же `QZSim.log`. Искать первую фатальную строку, затем первопричину выше; отделять базовый шум ванили (у QZ: «Duplicate appearance registry key … OutfitColor», «Console object … already exists», «Sentry … sentry.properties», «/NNEDenoiser invalid»). Две похожие ошибки могут значить противоположное — читать точный текст. [src: games/cities-skylines; techniques/running-xedit-on-wine; games/project-zomboid/b42; games/dcs-world]
4. **Отделить сейв от мода**: воспроизвести на новой кампании/лаб-сейве. [src: games/baldurs-gate-3/act2-bisect]
5. **Бисекция содержимого мода — первым делом**, а не после часов анализа: пересобрать мод с половиной ассетов, один запуск на раунд (95 сущностей → 11 запусков); подмены по одной; пробные ZZ-моды по одному типу ассета. [src: games/baldurs-gate-3/act2-bisect; games/binding-of-isaac; techniques/hosting-decomp]
6. **Крэш-дамп**: Журнал событий Windows (Application 1000, `Get-WinEvent`), `%LOCALAPPDATA%\QZSim\Saved\Crashes` (CrashContext.runtime-xml), минидамп; **у игры есть `QZSim-Win64-Shipping.pdb`** — адреса символизируются. Различать модуль: exe игры vs драйвер (nvwgf2umx и пр.) vs сторонний инжектор (UE4SS/dwmapi.dll у пользователя — интермиттентные крэши стороннего загрузчика встречались часто). Один адрес во всех дампах = детерминированно; зависание и крэш бывают одной ошибкой. [src: techniques/bannerlord-native-crashes; games/hitman/new-suit; games/middle-earth-shadow-of-war]
7. **Интермиттентное — 3+ запуска на конфигурацию и контроль без мода** (контроль 3/3 чисто). [src: games/hitman/new-suit]
8. **Каждый объяснённый крэш → правило валидатора**, чинить класс, а не случай. [src: techniques/editor-free-bannerlord-assets]

### 14.2 Частые причины, найденные другими
- **Shipping не проверяет данные, которые проверяет редактор** → плохие данные мода дают нативный крэш через секунды после причины; ошибки в PIE ≠ поведение в Shipping. Валидировать в своём пайплайне. [src: techniques/bannerlord-native-crashes]
- «Присутствует, но не разрешается» (битая ссылка, неверный ID/путь, длинное имя) чаще, чем «чего-то не хватает» — движок часто терпит отсутствие. [src: games/baldurs-gate-3/act2-bisect]
- **Тихий фолбэк хуже явной ошибки**: всё «работает», значения неверны (при отсутствии ассета мода игра молча показывает базовый). Логировать каждую причину «ничего не делаю, потому что…» (тихий отказ неотличим от мёртвой кнопки); fail-closed с одной строкой в лог. [src: techniques/frame-compositing; games/minecraft/re2-composite]
- **Система игры перезаписывает ваше значение** каждый кадр/при пересчёте — писать в авторитетный источник (DA/компонент-владелец), а не в производную копию; найти всех, кто пишет в эти данные (генератор посетителей/дни могут перекатывать выставленное модом); не воевать за одно поле — искать другой рычаг. [src: games/dark-souls-remastered; techniques/collision-and-combat-bridging; games/baldurs-gate-3/weapons]
- **Синхронное событие внутри вызова + обработчик, меняющий то же состояние → рекурсия и переполнение стека** → Delay/Next Tick, флаг занятости; соблюдать инварианты движка (рекурсивный поиск «до правильного ответа»). Не менять коллекцию во время обхода. [src: games/world-of-warcraft/addons; games/naruto-storm-4; games/borderlands-2]
- Обязательная логика спрятана в отладочной ветке → в Shipping-сборке её нет («меньшая сборка ведёт себя иначе»). Не оставлять Print/Breakpoint и отладочные флаги в BP перед упаковкой; диагностика не должна сама вешать игру (диагностика на уровне файла повесила игру). [src: games/watch-dogs/shadow-engine; games/project-zomboid/b41]
- Кэши/устаревшие артефакты (см. 4.2) и «правки не подействовали» — не пересобран бинарный ассет. [src: games/victoria-2; games/baldurs-gate-3/outfits]
- Наследование: изменение поведения родителя ломает потомков; перегрузка без Parent тихо заменяет поведение. [src: games/world-of-warcraft/playerbots-raid; games/cyberpunk-2077]
- Ссылки на объекты по индексу без поколения, кэшированные ссылки после уничтожения → событие уходит не тому объекту; IsValid каждый раз. [src: techniques/bridge-contracts; games/naruto-storm-4]
- Вызов, читающий у объекта несуществующие у его класса данные → NPE/крэш (Cast с проверкой). [src: games/project-zomboid/cdda-ants]
- Асинхронная запись + немедленное чтение → «0»; данные в памяти перезаписываются при выходе. [src: games/world-of-warcraft/azerothcore-modules]
- **Локаль**: RU-локаль пишет `9,50` вместо `9.50` — Python-скрипты, пишущие числа в ini/json/команды, — без локали (форматировать вручную/инвариантно). [src: games/fpv-logic]
- Сид случайности от «прошедшего времени ≈ 0» одинаков каждый раз — проверять распределение. [src: games/elden-ring/cs2]
- Фейковые/тестовые данные должны покрывать крайние значения реальных (баг прятался за «правдоподобными» 700 м). [src: games/minecraft/re2-composite]
- Один симптом — разные причины (сеть vs драйвер GPU vs лаунчер); маскирующий фикс ≠ корневой. Карта симптомов полезнее фиксов. [src: games/test-drive-unlimited-2 ×2]

### 14.3 Производительность
- **Профилировать, а не гадать** (после трёх неверных теорий сэмплинг нашёл реальную причину): для QZ — `stat unit`/`stat game`, Unreal Insights. Sustained-просадки — сначала проверить троттлинг железа (у пользователя ноутбук). [src: games/world-of-warcraft/server-ops; games/schedule-i]
- **В BP NPC/инструментов — никаких GetAllActorsOfClass/поиска на Tick**: кэшировать, обходить свои списки, N объектов за кадр; тяжёлое — не в колбэках движка, а со следующего тика; сотни посетителей с собственными таймерами/Niagara — общие пулы. Огромные списки создавать по требованию. [src: games/schedule-i; techniques/bannerlord-combat; games/halo-ce-elden-ring; games/baldurs-gate-3/clothing-sorter]
- Первая подгрузка тяжёлого ассета даёт фриз — soft-ссылки/асинхронная загрузка, разумные размеры текстур. Время старта растёт с числом пакетов — один мод = один pak (у нас так). [src: techniques/skinned-3d-models; techniques/editor-free]
- Бенчмарк: A/B старой и новой сборки на фиксированной сцене (FPS, 1% lows, мс/кадр); подробный лог сам тормозит — выключать после отладки. [src: games/risk-of-rain-2/helldiver; games/baldurs-gate-3/act2-bisect]
- **Ресурсы машины (16 ГБ ОЗУ)**: никогда одновременно редактор кита, UAT-кук и игру — нехватка памяти создаёт фальшивые «баги». Нагрузку, похожую на баг мода, повторить в одиночку. [src: techniques/prove-your-replay-bench-can-fail; techniques/tmodloader-labs]

## 15. Идеи модов (что делают в похожих играх) — применимость к QZ

Сложность для нашего пайплайна: **[DA]** — данные/ассеты через Python API кита, без логики; **[BP]** — нужен Blueprint-наследник/виджет; **[нет]** — вне возможностей кита (нужны хуки/нативный код — не делаем).

| Идея (откуда) | Как у QZ | Сложность |
|---|---|---|
| Новая одежда/наряды по слотам, сортировка совместимости по типам тел (BG3 outfits, clothing sorter) | Одежда посетителей: `QzClothingItemDataAsset` + меш на `metahuman_base_skel` по типам тел; генерация вариантов job.json | [DA] + модели пользователя |

| Шляпы/аксессуары на сокете (BG3 weapons/sheath, WoW attachments) | `QzCharacterHatDataAsset` (hat_mesh, hat_offset/extent, флаги коллизии) | [DA] + StaticMesh |
