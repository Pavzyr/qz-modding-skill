# Модель из Tripo → скин персонала в игре (без ошибок)

**Для замены доктора (Джорджи, `NPC.Skin.Doc`) есть готовый скилл `george_replace`** (`.claude/skills/george_replace/`: порядок команд, шаблоны, `inspect_glb.py`, `flat_maps.py`, `pose_check.py`). Этот файл — почему так и на чём мы обожглись.

Проверенный путь (2026-10-15/16, скин доктора Джорджи `NPC.Skin.Doc`). Каждый этап заканчивается
**проверкой-воротами**: не идти дальше, пока она не пройдена. В скобках `[ош.N]` — номер ошибки, которую мы реально допустили
(список в конце). Пользователь делает только этап 0 и финальную проверку в игре; всё остальное — я, без GUI.

## 0. Генерация (пользователь, Tripo)
- Экспорт **GLB**. Поза **T** (руки горизонтально). Polycount **~30k** (у Джорджи LOD0 ≈ 6.5k tris; 1.9M — непригодно [ош.1]).
- Только взрослый персонаж; узнаваемые чужие персонажи — риск по IP; NSFW — по правилам mod.io/игры.
- **Одна модель = одно имя файла.** Перегенерировал — новое имя (`..._v2.glb`), не перезаписывать старый файл [ош.34].

## 1. Подготовка (я)
- `tasklist`: **UnrealEditor.exe и игра закрыты** (не работать параллельно с редактором пользователя; игра держит файлы мода).
  Blender пользователя не трогать — свои прогоны только отдельным фоновым процессом `--background --factory-startup`.
- **Эталон** — FBX меша целевого NPC со скелетом игры (для доктора — экспорт `D2_Zheka` в `<папка модели>/D2_Zheka.FBX`, скелет `D1_Usmon_Skeleton`,
  119 костей: 52 тела + снаряжение + `*_end`). Для другого NPC — экспорт меша из UE (`op export`) и сверка `fbx_tree.py`.
- Бэкап: `Content` и `.uplugin` мода → отдельная папка `<Mod>_<что>_<дата>` вне кита; старый FBX → `backup_*`.
- Проверить `mtime` GLB и его хэш: если файл новее предыдущих текстур/FBX — всё пересобирать с нуля [ош.34].

## 2. Подгонка (stage fit)
Config (`<папка модели>/auto/config_*.json`):
```json
{"ref_fbx": ".../D2_Zheka.FBX", "model": ".../model.glb", "out_dir": ".../auto", "out_fbx": ".../auto/SK_MyChar_auto.fbx",
 "mesh_name": "SK_MyChar", "stage": "fit", "material_name": "<имя слота прошлого импорта>",
 "textures_dir": ".../textures", "texture_prefix": "T_MyChar"}
```
`"C:\Program Files\Blender Foundation\Blender 5.1\blender.exe" --background --factory-startup --python scripts/blender/auto_fit_skin.py -- config.json`

Что делает и на чём мы обожглись:
- Импорт эталона: объект скелета = **`root`** (узел Root из UE становится объектом; имя «Armature» → в UE «Failed to merge bones») [ош.5].
- Импорт GLB, **сварка** (remove doubles 0.0001 — AI-меши «рассыпаны») [ош.2], smooth.
- **Единицы**: headless-импорт FBX из UE даёт см (U ≈ 102 ед/м) — все пороги × U [ош.7].
- Рост по эталону, выравнивание **по коленям**, не по габаритам (у Джорджи рюкзак → сдвиг) [ош.4]. Центр по x — середина кончиков пальцев.
- Направления костей — **голова сустава → голова ребёнка** (хвосты костей UE-скелета не идут вдоль конечностей) [ош.8].
- Руки: конец = вершины у max|x|, трубка вокруг линии плечо→кисть (иначе волосы считаются рукой) [ош.9]; ключица к плечу модели;
  руки модели **удлиняются** до длины рук скелета (анимации UE навязывают длины костей) [ош.10]. Ноги — на щиколотки модели.
- Позу не угадывать на глаз: T или A — по отношению ширина/рост (T ≈ 0.87, A ≈ 0.6) [ош.3].

**Ворота:** открыть `1_fit_front.png`, `2_fit_side.png` (эталон красный): руки и ноги модели внутри/вдоль красных, по высоте плеч
совпадают; в `report.json` stretch рук ~1.0–1.3, `arm_z_vs_shoulder` ≈ 0.

## 3. Привязка, веса, экспорт, текстуры (stage all)
Тот же config со `"stage": "all"`. Порядок внутри скрипта **важен**:
1. Меш эталона Apply Armature → поза скелета → **Apply Pose as Rest**.
2. Привязка (ARMATURE_NAME) → Data Transfer весов с эталона (POLYINTERP_NEAREST).
3. **Снаряжение эталона → ближайшая кость тела** (67 групп: hos*, bags, belts, baloons, shield, `*_end`) [ош.11].
4. **Маски конечностей — после шага 3** (иначе вес шлангов падает на upperarm) [ош.12]: кости руки — только вершины, достижимые
   заливкой по рёбрам от кисти внутри трубки руки («крылья» волос) [ош.12]; calf/foot/ball — заливка от щиколотки + **вся обувь ниже
   щиколотки** (шпильки!) [ош.13]; thigh ≤ 0.20 м; clavicle ≤ 0.20 м. Пустые вершины → ближайший сустав торса.
5. **Волосы по цвету текстуры** (светлые и без оттенка + фильтр большинства) → только head → neck_01 → spine_03 → spine_02 по
   высоте; без таза/ног/рук [ош.14]. Для тёмных/цветных волос порог менять или `"hair": false` — смотреть рендер разметки.
6. **Юбка**: thigh-вес процедурный (перед 0.6, бок 0.3, зад 0), сглаженный — иначе шипы сзади при подъёме бедра [ош.15].
7. clean 0.01, limit 8, normalize.
8. Перед экспортом: скелет scale **0.01**, меш transform_apply (метры, scale 1) — иначе модель в UE в 100× больше [ош.7];
   имя слота материала = прошлому импорту [ош.18]. Экспорт: только ARMATURE+MESH, **add_leaf_bones=False, bake_anim=False**,
   use_armature_deform_only=False, smooth FACE.
9. **Текстуры извлекаются из того же GLB в том же прогоне** (сырые байты, без пересжатия) [ош.34].

**Ворота (все обязательны):**
- `3_bind_front`, `4/5_testpose_*`: руки **опущены** (тест-поза: +60° вокруг мировой Y для руки с d.x>0 [ош.16]), нет игл/крыльев.
- **Реимпорт-тест**: заново импортировать готовый FBX в чистую сцену, согнуть (руки вниз, колени, присед, наклон) и отрендерить
  **с теми jpg, что пойдут в UE** — встроенную в FBX текстуру подменить [ош.35].
- `fbx_tree.py new.fbx ref_or_prev.fbx`: LimbNode **119 = 119**, `root → pelvis`, расхождений 0.
- Масштаб при реимпорте: скелет scale 0.01, pelvis_z ≈ 0.996 м, рост ≈ 1.9 м.

## 4. Проверка пользователем в Blender (по желанию)
- `scripts/blender/check_in_blender.py` (поправить FOLDER/имена в начале): **новое окно Blender** → File → New → General →
  Scripting → вставить → Run. Импорт итогового FBX + текстура + позы на таймлайне 1–120 с метками. Только для просмотра.
- Если пользователь правил веса и экспортировал сам — **всегда** сравнить с авто-версией (кости, веса по вершинам) и почистить:
  `clean_user_export.py -- in.fbx out.fbx <material_name>`. Что было в ручном экспорте [ош.19–22]: Add Leaf Bones (+37 `*_end_end`
  → UE «Skeleton is missing bones… Please save the Skeleton»), Bake Animation (анимация таймлайна), нет Armature-модификатора
  (при повторном экспорте весов в файле нет), суффиксы `.001`. Ручные правки сохраняются (проверено: 0 расхождений весов).
- Подсказки пользователю по Weight Paint: синий = вес 0 (уже удалён); Strength 1 и Falloff Constant; лучше закрашивать нужной
  костью с Auto Normalize, чем стирать; точечно — Edit Mode → Vertex Groups → Remove/Assign; Overlays → Zero Weights → Active.

## 5. Ассеты в UE (задание, без GUI)
- Шаблон: `george_replace/templates/ue_job.template.json` → `py` op `scripts/examples/reimport_keep_settings.py`
  (`python -I scripts/qz_run_job.py <job.json>`). Снимок настроек → импорт поверх (legacy FBX: `Interchange.FeatureFlags.Import.FBX false`;
  существующий скелет; без новых материалов/текстур/physics) → восстановление.
- Новый мод с нуля: `create_mod` op (ставит `UUGC_Metadata.io_store_enabled=true`), импорт FBX со `skeleton=` скелета игры,
  импорт 3 текстур, свой `M_<Name>` из 3 текстур, DA `QzStaticNPCSkinDataAsset{npc_tag, mesh, materials {0: M_}}`.
- Правила UE:
  - на «regenerate Skeleton»/«save Skeleton» — **никогда** (это /Game) [ош.23]; ассеты только в `/<Mod>/`;
  - текстуры glTF: Normal = OpenGL → **Flip Green Channel**, sRGB off, Normalmap; RoughMetal sRGB off (G = roughness, B = metallic) [ош.25];
  - реимпорт текстур сбрасывает настройки → снимок/восстановление [ош.26]; `Texture2D.post_edit_change` в Python нет [ош.27];
  - BP_Doc держит override-материалы компонента → в DA **явно** `materials {0: M_<Name>}`, иначе «синий камуфляж» [ош.24];
  - в одном `QZSim/Mods` — **один мод на один скин** (второй мод на тот же скин перебивал первый → T-поза) [ош.29];
  - post-process AnimBP мода должен пропускать позу, иначе T-поза [ош.30].
- **Ворота:** отчёт `reimport.after`: скелет игры, слот → `M_<Name>`, physics на месте, verts_lod0 ~ ожидаемо (14.9k Blender →
  ~20k render), bounds z ≈ 94 см, текстуры 2048 с Flip Green у Normal.

## 6. PIE-проверка
- `UnrealEditor.exe QZSim.uproject -Installed -ExecCmds="py <abs>/probes/qz_pie_doc.py" -unattended -nosplash` (не
  -ExecutePythonScript). Результат `%LOCALAPPDATA%/QZSim/Saved/ModSchema/deep/pie_doc.json`.
- **Ворота:** `BP_Doc_C_0` → `/<Mod>/<Mesh>`, anim instance `ABP_Doc_C`; в `QZSim.log` нет `missing bones that SkeletalMesh`.
  Скины видны только в рантайме, не во вьюпорте редактора [ош.28].

## 7. Сборка
- `python -I scripts/qz_validate_mod.py <Mod>` → затем `python -I scripts/qz_package.py <Mod>`.
- Мод, созданный **мастером кита** (Create UGC), а не нашим `create_mod`:
  - `.uplugin` без `EngineVersion` / `GameVersion` / `ExplicitlyLoaded` → дописать (`5.7.0-0+UE5-QZ`, `RequiredModGameVersion`
    из DefaultGame.ini = 4, `true`) [ош.31];
  - `UUGC_Metadata.bIoStoreEnabled = false` → игра: «bUseIoStore values mismatch… will not be mounted» → op `set io_store_enabled true` [ош.32].
  Линтер ловит оба.
- **Ворота:** RESULT OK; `utoc_list.py` показывает меш, physics, DA, M_, 3 текстуры (+ubulk), UUGC_Metadata, ShaderArchive SM5/SM6.

## 8. Установка и проверка в игре
- Игра пользователя: ветка Steam **`modio`** (без неё модов нет; проверка — buildid в appmanifest), моды:
  `...\Quarantine Zone The Last Check\QZSim\Modio\<Mod>\` ← содержимое сборки `qz_package.py` (`<Mod>/`) (uplugin + Content/Paks/Windows).
  Писать в папку игры — только с согласия пользователя; перед копированием убедиться, что игра закрыта; старую папку мода удалить.
- Игру перезапустить полностью (мод подхватывается при старте) [ош.36].
- Если в игре не видно — `%LOCALAPPDATA%\QZSim\Saved\Logs\QZSim.log`: `Searching for UGC plugins`, `Added UGC plugin`,
  ошибки `bUseIoStore`, `below required`, `missing engine version`, `Another plugin of the same name`.
- Публикация на mod.io — только пользователь.
