# Передача моделей из Blender (чек-лист для пользователя + что делаю я)

Почему так — `kb-digest.md` §6–7 (опыт ~20 проектов переноса моделей в игры).

## Пользователь (Blender)
### Перед экспортом
- **Apply All Transforms** (Ctrl+A → All Transforms) и для арматуры, и для мешей; никакого отрицательного масштаба
  (иначе нормали наизнанку, предмет «уезжает» под землю после скиннинга).
- **Модификаторы** — применить осознанно (Edge Split/Mirror и др. меняют число и порядок вершин — веса «съезжают», появляются шипы).
- **Нормали**: Overlay → Face Orientation — снаружи не должно быть синего; при необходимости Recalculate Outside.
- Сварить дубли вершин (Merge by Distance) до децимации.
- Имена объектов/костей/материалов — латиницей, без пробелов, **без суффиксов `.001`**.
- **Слоты материалов**: осмысленные имена (Body, Head, Cloth…); если заменяем материалы базового меша по индексу — порядок и имена слотов как в эталоне.
- **UV**: внутри 0..1, если текстура не должна повторяться; без перекрытий, где разная текстура. Второй UV-канал не нужен (UE сделает lightmap сам).
- Пивот: как у эталона — у персонажа ноги в (0,0,0), у шляпы/аксессуара — точка крепления, у инструмента — точка хвата.

### Скелетные меши (одежда посетителей, персонал)
- Риг **ровно на скелете эталона**, который я выгружу из игры (те же имена костей, иерархия, rest pose; ik-кости не удалять).
  Новых костей не добавлять, не переименовывать. Пропорции — как у эталонного тела (анимации игры двигают и длины костей).
- Веса: лучше перенести с эталонного меша одежды игры (Data Transfer), потом поправить градиентами; невзвешенных вершин нет;
  нормализованы; ≤ 8 влияний на вершину. Shrinkwrap и перенос «по ближайшей грани» на тонких ремнях рвут меш.
- Одежда по типам тел: у игры одежда разложена по полу и типу тела — уточнить у меня, какие типы тел покрывать.

### Экспорт FBX
- Формат: FBX (Binary). Масштаб: Units = Metric; Unit Scale 0.01 ИЛИ «Apply Scalings: FBX Units Scale»; размеры в см, как в UE.
- Оси: Forward = −Y (или X Forward), Up = Z — **как в эталоне** (сверяемся на первом же импорте; лево/право может зеркалиться — фиксируем один раз).
- «Add Leaf Bones» — ВЫКЛ. «Armature → Only Deform Bones» — ВКЛ. «Tangent Space» — ВКЛ (без тангенсов — чёрные пятна).
- Анимации не экспортировать (если не просили); если просили — один take на файл, In Place или Root Motion — договориться заранее.
- Статические меши (шляпы, предметы, инструменты): без арматуры.

### Текстуры
- PNG/TGA, **степени двойки** (512/1024/2048), не больше, чем у похожих ассетов игры.
- BaseColor (sRGB); Normal — OpenGL (я переверну G при импорте) или DirectX — сообщить, какой; ORM/Roughness/маски — linear.
- Если альфы нет по смыслу — экспортировать без альфа-канала (иначе материал может стать полупрозрачным/«дырявым»).
- Яркость BaseColor сравнить с текстурами игры (свои часто темнее/ярче); залить паддинг UV (без чёрной каймы).

### Бюджет
- Персонаж ~30–60k треугольников, аксессуар ~2–10k (ориентир — меши игры той же категории; я сверю после импорта). LOD не обязательны.
- Записать версию Blender и настройки экспорта (я внесу в MODLOG).
- Положить файлы в папку, которую назовёт пользователь (например `<папка>\<Mod>\`).

## Автоматический перенос модели на скелет персонала (без ручной работы в Blender)
`scripts/blender/auto_fit_skin.py` — headless Blender, проверено на Tripo-модели (Т-поза, 30k tris) → скелет Джорджи
(D1_Usmon_Skeleton, эталон D2_Zheka.FBX). Запуск (Blender пользователя не трогает — отдельный фоновый процесс):
`blender.exe --background --factory-startup --python auto_fit_skin.py -- config.json`
config: `ref_fbx` (эталон из UE с LOD0), `model` (.glb/.fbx), `out_dir`, `out_fbx`, `mesh_name`, `stage` (`fit` = только
совмещение + рендеры, `all` = до экспорта), `material_name` (имя слота прошлого импорта → Reimport без лишнего слота).
Выход в out_dir: `report.json`, рендеры `1_fit_front/2_fit_side` (эталон красный), `3_bind_front`, `4/5_testpose_*`
(руки вниз + поворот головы), `fit_stage.blend` / `auto_result.blend`. Всегда смотреть рендеры, затем реимпорт-тест FBX.

Что делает и почему (грабли, на которых построено):
- **Единицы**: headless-импорт FBX из UE даёт объект скелета scale 1 и данные в см (U ≈ 102 ед/м), GUI-импорт — scale 0.01.
  Все пороги в скрипте умножаются на U; перед экспортом скелет → scale 0.01, меш → transform_apply (данные в м, scale 1),
  иначе UE получит модель в 100 раз больше. Сверять: реимпорт обоих FBX → pelvis_z ≈ 0.996 м, высота ≈ 1.9 м.
- **Хвосты костей UE-скелета не идут вдоль конечностей** → все направления/расстояния — по головам суставов (кость → голова ребёнка).
- **Руки**: конец руки = вершины у max|x|; направление — от медианы вершин у плеча к концу; центр модели по x = середина
  кончиков пальцев (асимметрия рук). Ключица поворачивается к точке плеча модели, upperarm→lowerarm→hand→middle_01 — по
  направлению руки. Руки модели **удлиняются** до длины рук скелета (анимации UE всё равно навязывают длины костей).
- **Ноги**: thigh→calf→foot направляются на щиколотку модели (кольцо вершин на высоте foot_*).
- Поза → `armature_apply` (меш эталона сначала Apply Armature) → привязка ARMATURE_NAME → DataTransfer POLYINTERP_NEAREST.
- **Снаряжение Джорджи** (67 групп: hos*, bags, belts, baloons, shield, *_end) → ближайшая кость тела.
- **Маски конечностей (главное против растяжений)**: модель Tripo — ОДИН связный меш (волосы, юбка, тело вместе), длинные
  волосы висят рядом с руками/бёдрами и от ближайшей поверхности Джорджи получают веса рук/ног → «крылья» при движении рук.
  Решение: заливка по рёбрам меша от кисти (в трубке 0.13 м вокруг линии руки) — только эти вершины могут иметь кости руки;
  calf/foot/ball — заливка от щиколотки в трубке ноги + вся обувь ниже щиколотки (каблуки-шпильки!); thigh — ≤0.20 м от
  бедра (юбка следует за ногами); clavicle — ≤0.20 м от ключицы. Остальное снимается, пустые вершины → ближайший сустав
  торса/головы. Порядок важен: маски применять ПОСЛЕ переноса снаряжения (иначе вес шлангов падает на upperarm).
- **Волосы по цвету текстуры** (пользователь увидел в Weight Paint вес pelvis на кончиках волос): вершина = волосы, если
  средний цвет BaseColor по её UV светлый и без оттенка (max>0.35, насыщенность<0.15) + 2 прохода фильтра большинства по
  соседям (убирает крапинки на коже). Tripo-модель: 6.6k из 14.9k вершин, разметка точная. Волосам — только head → neck_01 →
  spine_03 → spine_02 по высоте (линейно между суставами), без таза/ног/рук. `"hair": false` в config отключает (для
  моделей с цветными/тёмными волосами порог надо менять — смотреть рендер разметки). Цена: при наклоне волосы жёсткие.
- **Юбка**: скопированный вес thigh на задней части юбки при подъёме бедра (сидя) рвал её в шипы. Теперь для вершин зоны
  бедра (не нога, не волосы) thigh-вес процедурный: 0.6 × близость к бедру (0.10–0.20 м) × глубина ниже тазобедренного
  сустава (0–0.15 м) × «перёд» (сзади 0, бок 0.5, перед 1), 4 прохода сглаживания по соседям, сумма thigh ≤ 0.8, остальное —
  прежние веса торса пропорционально. Сидя юбка сзади висит, при шаге перед идёт за ногой.
- Тест-поза: поворот upperarm вокруг мировой Y на **+60° для руки с d.x>0** опускает руку (−60 поднимает).
Ограничения: волосы/юбка — жёсткие (без своих костей), в игре руки могут проходить сквозь волосы по бокам; тонкая
полировка — вручную в Weight Paint.
