# Рабочий цикл мода (адаптировано из universal-modder, MIT, github.com/rehan-remade/universal-modder)

У QZ есть официальный модкит, поэтому маршрут всегда один: **data/assets + Blueprint через ModioUGC-плагин**.
Маршруты universal-modder для чужих игр (UE4SS, pak-override `~mods/*_P.pak`, repak/retoc, FModel, AES-ключи, хуки)
здесь НЕ нужны и опасны: моды вне ModioUGC игра не валидирует, ломаются на обновлениях.
Подробные правила с источниками — `kb-digest.md` (разделы 1–16); здесь — сжатый порядок работы.

## Уровни доказательности (в MODLOG, notes.md и в ответах пользователю)
`[V]` проверено в игре (версия игры, что сделано) · `[M]` измерено · `[S]` статически (файлы/схема/inspect) · `[H]` гипотеза.
«Работает» говорю только после `[V]`, и только про проигранные сценарии. «Собрано/упаковано/смонтировано» ≠ «работает».
Чужой туториал/мод, не воспроизведённый нами, — «из источника, не проверено». Отчёт пользователя — «по словам пользователя».

## 0. Intake (коротко)
- Идея одной фразой + что значит «готово» (обычно: работает в игре + скрин/клип).
- Тип мода → рецепт в `mod-patterns.md`. Нужны ли модели от пользователя (Blender) → чек-лист в `blender-handoff.md`.
- Завести журнал мода: `QZSim/Mods/<Mod>/MODLOG.md` (шаблон `templates/MODLOG.md`). Всё, чего нет в журнале, теряется при сжатии контекста.
- Для сложного мода — «контракт» до кода: какая система игры за что отвечает, единицы/оси, жизненный цикл (старт, смена дня/уровня,
  загрузка сейва, удаление мода), что не покрыто. Для каждого изменяемого поля DA — **смысл** (по базовым ассетам игры, а не по имени поля).

## 1. Recon (по базе, не по памяти)
- Поля классов: `schema/key-classes.md`; реальные значения: `schema/samples.md`; что от чего наследуется: `schema/content-index.md`.
- Найти ближайший базовый ассет (`content-index.md`) — **Duplicate, а не Create с нуля** (пустой ассет теряет скрытые дефолты и обязательные поля).
- Найти, **какой именно ассет/список игра реально использует** для нужного контента (генераторы, теги, реестры UI), — иначе «загрузилось, но не выбирается».
- Посмотреть, как это сделали моды-образцы (`mod-patterns.md`, `scripts/utoc_list.py`); «нет в ванили» — не запрет.
- Если в схеме чего-то нет — дописать `qz_deep_dump.py`/`qz_probe_api.py` и перезапустить, а не гадать.
- В начале крупного проекта — заново поискать готовое (новые моды на mod.io, обновления кита) и указать авторство.

## 2. Vertical slice first
Один ассет до конца: создать → смонтировать → упаковать → проверить в игре. Только потом расширять.
Для скина: один NPC-тег; для симптома: один симптом + тестовый профиль; для инструмента: один инструмент.
Перед первым настоящим модом на новой версии кита — **контрольный прогон**: пустой ZZ-мод (только метаданные) → упаковать → игра
видит, ошибок нет. Тогда провал настоящего мода — это контент, а не пайплайн.

## 3. Lab / safety net
- Перед запуском редактора/UAT/игры: **не запущены ли у пользователя `QZSim-Win64-Shipping.exe` / `UnrealEditor.exe`** — если да, спросить.
  Чужие процессы не убивать; свои — только по PID. Тяжёлые процессы по одному (16 ГБ ОЗУ: редактор, UAT и игра не одновременно).
- Перед тестом в игре — **бэкап сейвов** `%LOCALAPPDATA%\QZSim\Saved\SaveGames\76561198154708427` (+ попросить пользователя сохраниться);
  тесты — на новой кампании/лаб-сейве; после — сверить, что его сейв не тронут.
- Не трогать `QZSim/Content` (/Game) и файлы установки игры. Всё — в `QZSim/Mods/<Mod>/`.
- Тестовые моды-пробы называть `ZZ*` и удалять после проверки. Не держать одновременно локальную копию и подписку mod.io с тем же именем.
- Синтетический ввод/клики в окно игры — только с согласия и когда пользователь не за клавиатурой.

## 4. Build (скриптами)
- `scripts/qz_run_job.py job.json` — каркас плагина + задание в редакторе (см. SKILL.md, «Инструменты»). Ничего руками в папке мода —
  всё воспроизводимо заданиями; задания (или их суть) — в MODLOG.
- Идемпотентность: повторный запуск задания не должен ломать мод (create_* переиспользуют существующие ассеты).
- `set` полей: сначала `inspect` текущего значения (незаданное поле = дефолт источника, не ноль); у дубликата переписать **самоссылки**
  (поля, указывающие на базовый ассет/его теги, меш → материалы → BP — на свои копии).
- Новый контент — новые имена/теги с префиксом мода рядом с ванилью; базовые теги/DA не удалять и не переименовывать;
  подмена базового ассета тем же путём — крайняя мера (заменяет всё определение, после обновления игры теряет новые поля).

## 5. Verify — оракул это игра/редактор, а не моё чтение кода
Лестница (каждая ступень — отдельная проверка):
1. **Офлайн**: отчёт задания + `inspect` (значения реально записались, ссылки разрешаются, слоты материалов верны) + `qz_validate_mod.py`.
2. **Упаковано**: UAT «BUILD SUCCESSFUL» и нет `Error` нашего мода в логе кука; `utoc_list.py` — в пакете ровно ожидаемые ассеты;
   zip читается обратно; zip новее последних правок ассетов.
3. **Смонтировано**: в `%LOCALAPPDATA%\QZSim\Saved\Logs\QZSim.log` монтирование мода (`LogModioUGC`, `LogQzModio`, нет «Some mods were not loaded»).
   Лог копировать сразу (редактор кита пишет в тот же файл; при следующем старте перезапишется).
4. **Используется и видно**: контент реально появляется в игре (симптом у посетителя, инструмент в руках/колесе, кампания в списке, текст на RU).
   Тестовое значение/цвет/текст — **заметно отличный от ванили**, иначе «совпало» ничего не доказывает. Скриншот — открыть и описать, свежесть по mtime.
5. **Сохранение**: новая кампания → играть → сохранить → выйти в меню → загрузить; полный перезапуск игры.
6. **Удаление**: выключить мод → перезапуск → игра как ваниль, сейв грузится.
- Финальная проверка — только упакованный мод в Shipping-игре (PIE/редактор прячут проблемы релиза); стенды не видят окружение пользователя — финал за ним.
- Хорошая проверка **умеет падать** (проверить на заведомо сломанном варианте); при массовом первом провале — сначала подозревать саму проверку.
- **Circuit breaker:** одна и та же ошибка 3 раза подряд → остановиться, записать в журнал что известно, сменить подход или спросить пользователя.

## 5a. Когда не работает / падает (порядок)
1. Ваниль без мода на этом ПК — та же проблема? Пустой ZZ-мод — тоже?
2. Мод вообще загрузился (лог монтирования, маркер версии)? Именно новая сборка?
3. Лог: первая фатальная строка → первопричина выше; базовый шум ванили отделить (список в kb-digest §14).
4. Сейв или мод? — повторить на новой кампании.
5. **Бисекция содержимого мода** (половина ассетов → упаковать → запуск), а не часы теорий.
6. Крэш: Журнал событий Windows (Application 1000), `Saved\Crashes`, минидамп + `QZSim-Win64-Shipping.pdb`; чей модуль (игра / драйвер / UE4SS-инжектор).
7. Интермиттентное — 3+ запуска с модом и без. Найденную причину — правилом в `qz_validate_mod.py`.

## 6. Package & publish
- Lint перед публикацией (`scripts/qz_validate_mod.py`): uplugin без BOM, EngineVersion/GameVersion/ExplicitlyLoaded,
  нет зависимостей на ассеты, созданные в /Game, нет абсолютных путей/секретов (ApiKey mod.io из конфигов кита!), нет отладочных ассетов, есть README/описание.
- В мод — только своё: никаких файлов игры/кита и ассетов из других игр (это только личные сборки, не mod.io).
- Хранить предыдущий рабочий zip для отката; версия мода растёт с каждой сборкой, имя плагина не меняется.
- Публикует всегда пользователь (mod.io). Я готовлю zip, описание, changelog, скриншоты, требования сайта (превью и т.п.).
- В описании: версия игры/кита и GameVersion, дата, что проверено и что нет, зависимости (другие моды по тегам), совет подписываться
  между днями/кампаниями, что подмена базового контента действует во всех кампаниях, честное указание, что мод собран с помощью ИИ, если пользователь не против.
- **После каждого обновления игры или кита** — пересобрать мод и пройти лестницу проверки заново.

## 7. Field note
После каждого мода — запись в `references/notes.md` (что сработало, грабли «симптом → причина → решение», с уровнем доказательности),
новые паттерны — в `mod-patterns.md`. Документированный тупик и исправленный диагноз («думали X, оказалось Y») тоже ценны.
В длинных сессиях периодически перечитывать SKILL.md (правила «затухают», особенно после сжатия контекста).
